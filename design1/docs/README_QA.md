# Design 1 코드 질문과 답 (DE2_Project1.vhd)

발표 대비용으로 코드에 대해 직접 물어본 질문과 답을 모았다. 특히 "다른 방법이면 안 되나?" 같은 질문은 발표에서 나올 가능성이 높다.
나중에 코드 설명 HTML(`DE2_Project1_code_explanation.html`)에 옮길 내용이다.

## 1. 7세그먼트는 0일 때 켜진다. 보통 1일 때 켜지지 않나?

**DE2에서는 0일 때 켜지는 게 맞다.** 관례가 아니라 보드 회로가 그렇게 되어 있다.

- DE2의 HEX0~7은 **공통 애노드(common anode)** 방식이다. 각 세그먼트 LED의 애노드(+)는 모두 3.3 V에 묶여 있고, 캐소드(−)가 FPGA 핀에 바로 연결되어 있다.
- FPGA 핀이 **0(Low)**이면 3.3 V → LED → 핀으로 전류가 흘러 **켜진다.**
- 핀이 **1(High)**이면 양쪽 전압이 같아 전류가 없으니 **꺼진다.**

이렇게 0일 때 동작하는 신호를 **active-low**라고 한다. DE2 User Manual에도 7세그먼트는 Low일 때 켜진다고 되어 있다. 1일 때 켜지는 보드는 **공통 캐소드** 방식이다. 즉 보드마다 다르다.

코드의 표 `SEG7`도 이 기준이다. 숫자 0은 `"1000000"`인데, 꺼지는 건 g(가운데 획) 하나뿐이고 나머지 6개가 켜진다.

**다른 방법:** 디코더 표를 "1 = 켜짐"으로 쓰고, 핀으로 내보낼 때만 뒤집어도 된다(`HEX0 <= not SEG7(d0);`). 동작은 같고 표를 읽기가 쉬워지는 대신 코드가 조금 길어진다.

## 2. 문자 코드 상수 (29~33번 줄)

```vhdl
-- character codes : 0~15 = hex digit 0~F, 16 = blank, 17 = '-', 18 = 'r'
constant BLANK : integer := 16;
constant MINUS : integer := 17;
constant CH_R  : integer := 18;
constant CH_E  : integer := 14;   -- same shape as hex E
```

**7세그먼트에 띄울 "글자"마다 번호를 붙여 둔 것이다.**

- `d0`~`d7`(45번 줄, `integer range 0 to 18`)에는 각 자리에 띄울 **글자 번호**가 들어간다.
- 마지막 줄에서 이 번호로 표 `SEG7`을 찾아 실제 세그먼트 패턴으로 바꾼다: `HEX0 <= SEG7(d0); ...`

| 번호 | 글자 | 패턴 (g f e d c b a, 0 = 켜짐) | 쓰는 곳 |
|---|---|---|---|
| 0~9 | 숫자 0~9 | | 카운터, 계산 결과 |
| 10~15 | A, b, C, d, E, F | | 16진수 모드(SW3) |
| 16 `BLANK` | 빈칸 | `1111111` (전부 꺼짐) | 안 쓰는 자리 |
| 17 `MINUS` | `-` | `0111111` (g만) | 음수 결과 |
| 18 `CH_R` | `r` | `0101111` (e, g) | `Err`, 나머지 표시 |
| 14 `CH_E` | `E` | 16진수 E와 같은 칸 | `Err` |

세그먼트 위치:

```
 aaa
f   b
 ggg
e   c
 ddd
```

**쓰이는 곳 (131~158번 줄):**
- 프로세스 시작에서 8자리를 모두 `BLANK`로 깔아 두고 필요한 자리만 덮어쓴다. 자리를 빠뜨려도 이상한 글자 대신 빈칸이 된다.
- 0으로 나누기: `d2 <= CH_E; d1 <= CH_R; d0 <= CH_R;` → 오른쪽 세 자리에 `Err`
- 나눗셈: `d3 <= quot; d1 <= CH_R; d0 <= remain;` → 예: 7÷2면 `3 r1`
- 음수: `if neg = '1' then d3 <= MINUS;` → 결과 앞에 `-`

**이렇게 짠 이유:**
1. `d1 <= 18`보다 `d1 <= CH_R`이 읽기 쉽고, 번호를 바꿀 때 한 곳만 고치면 된다.
2. "무슨 글자를 띄울지"(계산 프로세스)와 "어떤 획을 켤지"(표 하나)를 나눴다. 8자리가 같은 표를 쓴다.
3. `integer range 0 to 18`로 범위를 정하면 합성기가 5비트만 쓴다. 범위 없는 `integer`는 32비트다.

## 3. `CH_E = 14`는 왜 필요한가? 없애면 안 되나?

**꼭 필요하지는 않다.** 없애도 회로와 동작은 완전히 같다. 합성기는 `CH_E`를 그냥 14로 바꿔 넣는다.

```vhdl
d2 <= 14;    d1 <= CH_R;  d0 <= CH_R;    -- CH_E 없이
d2 <= CH_E;  d1 <= CH_R;  d0 <= CH_R;    -- 지금
```

그래도 이름을 붙인 이유:
1. **뜻이 다르다.** 16진수 모드에서 `d0 <= result mod 16`이 14가 되는 건 "숫자 14"이고, `Err`의 14는 "글자 E"다. 값은 같아도 의도가 다르다. `d2 <= 14`라고 쓰면 "왜 14를 띄우지?" 하고 멈추게 된다.
2. **옆 줄과 짝이 맞다.** `r`은 `CH_R`이라는 이름을 쓰므로 E도 이름을 쓰면 `Err`가 한눈에 읽힌다.
3. **표에 칸을 추가하지 않는다.** E는 16진수 E와 모양이 같아서 새 번호를 만들지 않고 14번에 이름만 하나 더 붙였다.

없애면 1줄이 줄지만(간결함이 평가 항목), 대신 `-- "Err" (14 = E)` 같은 주석이 필요하다. **결정: 남긴다.**

## 4. 버튼 신호를 왜 한 클럭 늦춰서 저장하나?

```vhdl
signal k1, k2 : std_logic_vector(3 downto 0) := "1111";  -- buttons now / one clock ago
...
k1 <= KEY;    -- 이번 클럭에 읽은 버튼
k2 <= k1;     -- 그 직전 클럭에 읽은 버튼
if k2(3) = '1' and k1(3) = '0' then ...   -- 직전엔 안 눌림, 지금은 눌림
```

**누른 "순간"을 한 번만 잡기 위해서다(에지 검출).** 이전 값과 현재 값을 비교해야 순간을 알 수 있고, 이전 값을 기억하려면 한 클럭 늦춘 복사본이 필요하다.

**늦추지 않으면:** `if KEY(3) = '0' then cnt <= cnt + s1;`처럼 쓰면, 클럭이 50 MHz라 버튼을 0.1초만 눌러도 500만 번 더해진다.

KEY3을 눌렀다 뗄 때의 시간 순서:

| 클럭 | KEY(3) | k1 | k2 | k2='1' and k1='0' |
|---|---|---|---|---|
| 1 | 1 | 1 | 1 | 아니오 |
| 2 | **0** (누름) | 1 | 1 | 아니오 |
| 3 | 0 | **0** | 1 | **예 → 한 번 더함** |
| 4 | 0 | 0 | 0 | 아니오 (계속 누르고 있어도) |
| n | 1 (뗌) | 0 | 0 | 아니오 |

**KEY와 k1을 바로 비교하지 않고 k1, k2 둘 다 쓰는 이유:**
1. 버튼은 클럭과 상관없이 아무 때나 바뀐다. 클럭 에지 바로 근처에서 바뀌면 플립플롭이 잠깐 불안정한 상태(메타스테이블)가 될 수 있다. KEY를 한 번 플립플롭(k1)에 받아 두고 그 결과만 쓰면 위험이 크게 줄어든다.
2. KEY를 직접 쓰면 `if` 네 개가 서로 다른 순간의 KEY를 볼 수 있다. k1, k2는 클럭마다 한 번만 바뀌는 레지스터라 모든 조건이 같은 값을 본다.

**디바운스(채터링 방지)는 왜 안 했나:** DE2의 KEY는 보드에 슈미트 트리거 디바운스 회로가 있다.

## 5. 초기값이 0이면 오작동하나? k1, k2는 플립플롭인가? NGT를 쓰는 건가?

**초기값 0이어도 오작동하지 않는다.** (처음 답할 때 "오작동할 수 있다"고 했는데 틀렸다.)

조건이 1→0(직전 1, 지금 0)만 보기 때문이다. k1, k2가 0으로 시작하고 안 누른 상태(KEY=1)로 전원을 켜면:

| 클럭 | KEY | k1 | k2 | 조건 |
|---|---|---|---|---|
| 시작 | 1 | 0 | 0 | 아니오 (k2가 0) |
| 1 | 1 | 1 | 0 | 아니오 (k1이 1) |
| 2 | 1 | 1 | 1 | 아니오 |

오히려 `"1111"`로 시작하면, **전원을 켤 때 버튼을 누르고 있으면** 첫 클럭에 k1=0, k2=1이 되어 한 번 누른 것으로 처리된다. 둘 다 실제로 문제 될 일은 거의 없다. `"1111"`은 동작에 꼭 필요하지 않고, "버튼이 안 눌린 상태(1)로 시작한다"는 의도를 보여 주는 값이다.

**k1, k2는 D 플립플롭이다.** `if rising_edge(CLOCK_50) then` 안에서 대입하는 신호는 Quartus가 D-FF로 만든다. 각 4비트이니 FF가 4개씩, 비트마다 2단 시프트 레지스터다.

```
KEY ─▶[D-FF]─ k1 ─▶[D-FF]─ k2
         ▲             ▲
     CLOCK_50      CLOCK_50
```

초기값 `:= "1111"`도 Cyclone II에서 실제로 반영된다(FPGA 설정 직후 FF 값을 1로 맞춘다).

**NGT를 쓰는가 — 두 가지를 구분한다.**
1. **플립플롭이 동작하는 시점은 CLOCK_50의 PGT(상승 에지)다.** `rising_edge(CLOCK_50)`.
2. **코드가 잡아내는 버튼 변화는 KEY의 NGT(1→0)다.** `k2='1' and k1='0'`.

버튼을 클럭으로 쓰지 않는다(`falling_edge(KEY(3))` 아님). 50 MHz 클럭의 PGT마다 버튼을 읽어 두고, 이전 값과 비교해 NGT가 있었는지 **논리로 판정**한다. 그래서 회로 전체가 클럭 하나로만 움직이는 **동기식 설계**가 된다. 버튼을 클럭으로 쓰면 클럭이 여러 개가 되어 타이밍 분석이 어려워진다.

## 6. 누르는 순간이 왜 KEY의 NGT인가? PGT면 안 되나?

**DE2의 버튼 회로가 그렇게 되어 있다.**

```
3.3 V
  │
 [저항]  풀업
  │
  ├──────▶ (슈미트 트리거) ──▶ FPGA 핀 KEY(n)
  │
 [버튼]
  │
 GND
```

- 안 누름: 풀업 저항이 핀을 3.3 V로 당긴다 → **1**
- 누름: 버튼이 핀을 GND에 붙인다 → **0**

그래서 누르는 순간 1→0(NGT), 떼는 순간 0→1(PGT)이다. 7세그먼트와 같은 active-low다.

**PGT로 해도 된다.** 대신 손을 **뗄 때** 반응한다.

```vhdl
if k2(3) = '0' and k1(3) = '1' then   -- 직전 0, 지금 1 → 버튼을 뗀 순간
```

| | NGT (지금 코드) | PGT |
|---|---|---|
| 반응 시점 | 누르는 순간 | 손을 떼는 순간 |
| 체감 | 누르자마자 숫자가 바뀜 | 떼야 바뀜 |

사람은 누르면 바로 반응하기를 기대하므로 NGT를 쓴다.
