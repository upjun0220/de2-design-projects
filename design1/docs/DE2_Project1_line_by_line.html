머리말 주석라이브러리와 입출력 핀선언부 — 상수, 신호, 표카운터LED와 잭팟 판정계산기7세그 표시 결정출력 연결주석이 있던 원본예상 질문알아둘 점
전체 흐름
  1. 입력: 스위치 SW와 버튼 KEY를 읽는다. SW0이 카운터/계산기를 고른다.
  2. 카운터 모드: 버튼을 누르는 순간 cnt가 바뀐다(0~9999). 계산기 모드: 스위치 값으로 매번 다시 계산한다.
  3. 표시: 결과를 문자 코드로 바꿔 7세그(HEX)와 LED(LEDR/LEDG)에 내보낸다. 777이면 잭팟 효과가 나온다.

머리말 주석

코드에서는 지웠고, 사용법을 요약해 둔 주석이었다. 원문을 그대로 보여 준다.

코드에서 삭제한 주석 (원문)
-- DE2 Design Project #1 : Counter + One Digit Calculator (with bonus)
과제 이름과 보너스 포함 여부. --로 시작하는 줄은 주석이라 회로에 영향이 없다.
코드에서 삭제한 주석 (원문)
-- SW0 : 0 = counter, 1 = calculator
SW0이 카운터/계산기를 고르는 스위치다. 0이면 카운터, 1이면 계산기.
코드에서 삭제한 주석 (원문)
-- Counter    : SW1 = mode, KEY3/KEY2/KEY1 = change value, KEY0 = reset
--              HEX3~0 = value, LEDR = value in binary
--              jackpot at 777 : green LEDs stay on, HEX7~4 show 7777
카운터 모드 요약. SW1은 증감 크기를 고르고(0: +1/+2/-1, 1: +5/+10/-5), KEY3/KEY2/KEY1이 값을 바꾸고 KEY0이 0으로 리셋한다. 값은 HEX3~0에 십진수로, LEDR에 이진수로 나온다. 값이 777이면 잭팟.
코드에서 삭제한 주석 (원문)
-- Calculator : SW17~14 = A, SW13~10 = B, SW2~1 = operation (00 +, 01 -, 10 *, 11 /)
--              SW3 = 0 : decimal (0~9),  SW3 = 1 : hexadecimal (0~F)
--              A on HEX6, B on HEX4, result on HEX3~0
--              division shows "quotient r remainder", for example 7 / 3 -> "2 r1"
계산기 모드 요약. A는 SW17~14, B는 SW13~10(각 4비트), 연산은 SW2~1(00 덧셈, 01 뺄셈, 10 곱셈, 11 나눗셈). SW3=0이면 십진수(0~9), 1이면 16진수(0~F). A는 HEX6, B는 HEX4, 결과는 HEX3~0. 나눗셈은 몫 r 나머지 형태.

선언부 — 상수, 신호, 표

16줄
16architecture behavior of DE2_Project1 is
architecture: entity가 실제로 어떻게 동작하는지 쓰는 본문.

18    constant MINUS : integer := 17;
19    constant CH_R  : integer := 18;

카운터 값. integer range 0 to 9999로 범위를 제한해 필요한 비트 수만 쓴다. 초기값 0.

26줄
26    signal base   : integer range 10 to 16;
base: 결과를 몇 진수로 보일지. 십진수 모드이면 10, 16진수 모드이면 16.

+, -, × 결과(뺄셈은 절댓값). 최대 15×15=225라서 0~255면 충분하다.

33줄

카운터

버튼을 누르는 순간 한 번만 값이 바뀌고 0~9999에서 멈춘다.

42~43줄
42    s1 <= 1 when SW(1) = '0' else 5;
43    s2 <= 2 when SW(1) = '0' else 10;
증감 크기를 고른다. when ... else는 조건에 따라 값을 고르는 대입문이다. SW1=0이면 s1=1, s2=2, SW1=1이면 s1=5, s2=10.
45~46줄
45    process (CLOCK_50)
46    begin
process (CLOCK_50): 클럭 신호가 바뀔 때 실행되는 블록.
47줄
47        if rising_edge(CLOCK_50) then
rising_edge: 클럭이 0→1로 올라가는 순간에만 안쪽을 실행한다(동기 회로).
48~49줄
48            k1 <= KEY;
49            k2 <= k1;
버튼을 두 단계로 받는다. 매 클럭 k1=지금 KEY, k2=한 클럭 전 k1. 그래서 k2='1' and k1='0'이면 '방금 눌렸다(1→0)'는 뜻이다. 길게 눌러도 한 번만 세는 이유다.
50줄
50            if SW(0) = '0' then
계산기 모드에서는 카운터가 변하지 않도록 SW(0)='0'일 때만 아래를 실행한다.
51~52줄
51                if k2(0) = '1' and k1(0) = '0' then
52                    cnt <= 0;
KEY0을 누르는 순간 0으로 리셋. elsif 체인이라 우선순위는 KEY0 > KEY3 > KEY2 > KEY1이다. 이 우선순위는 두 에지가 같은 클럭(20 ns)에 겹칠 때만 적용된다. 손으로 누르면 보통 몇 ms 어긋나서 두 에지가 따로 잡히고, 나중에 잡힌 쪽이 마지막에 반영된다.
53~54줄
53                elsif k2(3) = '1' and k1(3) = '0' then
54                    if cnt + s1 > 9999 then cnt <= 9999; else cnt <= cnt + s1; end if;
KEY3: s1만큼 증가. cnt + s1 > 9999이면 9999에 고정(포화).
55~56줄
55                elsif k2(2) = '1' and k1(2) = '0' then
56                    if cnt + s2 > 9999 then cnt <= 9999; else cnt <= cnt + s2; end if;
KEY2: s2만큼 증가, 같은 포화 처리.
57~58줄
57                elsif k2(1) = '1' and k1(1) = '0' then
58                    if cnt < s1 then cnt <= 0; else cnt <= cnt - s1; end if;
KEY1: s1만큼 감소. 0보다 작아지면 0에 고정.
59~62줄
59                end if;
60            end if;
61        end if;
62    end process;
열려 있던 if와 process를 닫는다.

LED와 잭팟 판정

빨간 LED는 항상 이진수 표시, 777이면 초록 LED가 모두 켜진 채 유지된다.

64줄
64    jp   <= '1' when SW(0) = '0' and cnt = 777 else '0';
잭팟 판정: 카운터 모드이고 값이 777일 때 jp=1.
65줄
65    LEDR <= std_logic_vector(to_unsigned(cnt, 18)) when SW(0) = '0' else (others => '0');
LEDR: 카운터 모드이면 cnt를 18비트 이진수로 바꿔 출력한다(최대 9999는 14비트라 위 4개는 0). 잭팟(777)일 때도 똑같이 이진수를 보여 준다. 계산기 모드면 전부 0.
66줄
66    LEDG <= (others => jp);
LEDG: (others => jp)는 8개 LED를 모두 jp 값으로 채운다는 뜻이다. 잭팟이면 전부 켜진 채 유지되고(깜빡이지 않는다), 아니면 꺼진다.

계산기

스위치 값이 바뀔 때마다 다시 계산하는 조합 회로다.

68~69줄
68    a      <= to_integer(unsigned(SW(17 downto 14)));
69    b      <= to_integer(unsigned(SW(13 downto 10)));
SW(17 downto 14)를 unsigned로 보고 to_integer로 정수 0~15를 만든다. 이것이 A, 같은 식으로 SW13~10이 B.
70줄
70    base   <= 16 when SW(3) = '1' else 10;
16진수 모드(SW3=1)이면 base=16, 아니면 10.
71줄
71    valid  <= '1' when SW(3) = '1' or (a < 10 and b < 10) else '0';
16진수 모드이거나 A, B가 모두 10 미만이면 유효. 십진 모드에서 10 이상이면 무효.
72~74줄
72    result <= a + b      when SW(2 downto 1) = "00" else
73              abs(a - b) when SW(2 downto 1) = "01" else
74              a * b;
연산 결과. 연산(SW2~1)에 따라 when ... else로 고른다. 00 덧셈, 01 뺄셈, 그 밖에는 곱셈. 뺄셈은 abs(a - b)로 큰 수에서 작은 수를 뺀 절댓값을 구하고, 음수 기호는 표시 단계에서 a < b일 때 붙인다. 나눗셈(11)은 표시 단계에서 직접 계산하므로 여기 값은 쓰지 않는다.

7세그 표시 결정

각 HEX에 무엇을 보일지 문자 코드(d(0)~d(7))로 정한다.

76~77줄
76    process (SW, cnt, a, b, base, result, valid)
77    begin
표시 내용을 정하는 process. 값이 바뀌면 다시 계산하는 조합 회로.
78줄
78        d <= (others => BLANK);
먼저 8칸 모두 빈칸으로 둔다. (others => BLANK)는 배열의 모든 칸을 한 값으로 채운다는 뜻이다. 아래에서 필요한 칸만 덮어쓴다.
80줄
80        if SW(0) = '0' then
카운터 모드.
81~84줄
81            d(3) <= cnt / 1000;
82            d(2) <= (cnt / 100) mod 10;
83            d(1) <= (cnt / 10) mod 10;
84            d(0) <= cnt mod 10;
값을 자릿수로 쪼갠다. 예) 1234 → /1000=1, /100 mod 10=2, /10 mod 10=3, mod 10=4. HEX3(천)~HEX0(일).
85줄
85            if cnt = 777 then d(7 downto 4) <= (others => 7); end if;
잭팟(777)이면 HEX7~4에 7을 4개 띄운다. d(7 downto 4)는 배열의 네 칸을 한꺼번에 가리킨다.
86줄
86        else
계산기 모드.
87~88줄
87            if SW(3) = '1' or a < 10 then d(6) <= a; end if;
88            if SW(3) = '1' or b < 10 then d(4) <= b; end if;
A는 HEX6, B는 HEX4에 표시. 십진 모드에서 10 이상이면 빈칸으로 둔다.
89줄
89            if valid = '1' then
입력이 유효할 때만 결과를 표시한다.
90줄
90                if SW(2 downto 1) /= "11" then
/=는 '같지 않다'. 나눗셈이 아닌 연산(+, -, ×)이면 아래 두 단계로 표시한다.
91줄
91                    if SW(2 downto 1) = "01" and a < b then d(3) <= MINUS; end if;
뺄셈에서 A가 B보다 작으면 결과가 음수이므로 HEX3에 '-'.
92~93줄
92                    d(1) <= result / base;
93                    d(0) <= result mod base;
결과를 base로 나눈 몫이 HEX1, 나머지가 HEX0이다. 16진수 모드는 16으로 나눠 225 → E1, 십진수 모드는 10으로 나눠 십의 자리와 일의 자리가 된다(최대 81).
94~95줄
94                elsif b = 0 then
95                    d(2) <= CH_E;  d(1) <= CH_R;  d(0) <= CH_R;
0으로 나눔: HEX2~0에 ' Err'(E, r, r).
96~97줄
96                else
97                    d(3) <= a / b;  d(1) <= CH_R;  d(0) <= a mod b;
나눗셈: HEX3=몫, HEX1='r', HEX0=나머지. 예) 7÷3 → 2 r1. 이 줄은 B≠0일 때만 실행되므로 0으로 나누는 일이 없다.
98~101줄
98                end if;
99            end if;
100        end if;
101    end process;
열려 있던 if들과 process를 닫는다.

주석이 있던 원본

저장소의 코드에는 주석이 없다. 지운 주석을 포함한 원본(121줄)이다.

펼치기
1-- DE2 Design Project #1 : Counter + One Digit Calculator (with bonus)
2-- SW0 : 0 = counter, 1 = calculator
3-- Counter    : SW1 = mode, KEY3/KEY2/KEY1 = change value, KEY0 = reset
4--              HEX3~0 = value, LEDR = value in binary
5--              jackpot at 777 : green LEDs stay on, HEX7~4 show 7777
6-- Calculator : SW17~14 = A, SW13~10 = B, SW2~1 = operation (00 +, 01 -, 10 *, 11 /)
7--              SW3 = 0 : decimal (0~9),  SW3 = 1 : hexadecimal (0~F)
8--              A on HEX6, B on HEX4, result on HEX3~0
9--              division shows "quotient r remainder", for example 7 / 3 -> "2 r1"
10library ieee;
11use ieee.std_logic_1164.all;
12use ieee.numeric_std.all;
13
14entity DE2_Project1 is
15    port (
16        CLOCK_50 : in  std_logic;
17        KEY      : in  std_logic_vector(3 downto 0);
18        SW       : in  std_logic_vector(17 downto 0);
19        LEDR     : out std_logic_vector(17 downto 0);
20        LEDG     : out std_logic_vector(7 downto 0);
21        HEX0, HEX1, HEX2, HEX3, HEX4, HEX5, HEX6, HEX7 : out std_logic_vector(6 downto 0)
22    );
23end DE2_Project1;
24
25architecture behavior of DE2_Project1 is
26    -- character codes : 0~15 = hex digit 0~F, 16 = blank, 17 = '-', 18 = 'r'
27    constant BLANK : integer := 16;
28    constant MINUS : integer := 17;
29    constant CH_R  : integer := 18;
30    constant CH_E  : integer := 14;   -- same shape as hex E
31
32    signal k1, k2 : std_logic_vector(3 downto 0) := "1111";  -- buttons now / one clock ago
33    signal cnt    : integer range 0 to 9999 := 0;            -- counter value
34    signal s1, s2 : integer range 0 to 10;                   -- step size
35    signal a, b   : integer range 0 to 15;                   -- calculator inputs
36    signal base   : integer range 10 to 16;                  -- number base of the result : 10 (decimal) or 16 (hexadecimal)
37    signal result : integer range 0 to 255;                  -- result of + - * (absolute value)
38    signal valid  : std_logic;                               -- 0 = decimal mode and A or B is 10 or more
39
40    -- what each 7-segment shows : d(0) is HEX0, ..., d(7) is HEX7
41    type digit_array is array (7 downto 0) of integer range 0 to 18;
42    signal d : digit_array;
43
44    -- 7-segment pattern of each character code (a segment lights up when 0)
45    type seg_table is array (0 to 18) of std_logic_vector(6 downto 0);
46    constant SEG7 : seg_table := (
47        "1000000", "1111001", "0100100", "0110000", "0011001",   -- 0 1 2 3 4
48        "0010010", "0000010", "1111000", "0000000", "0010000",   -- 5 6 7 8 9
49        "0001000", "0000011", "1000110", "0100001", "0000110", "0001110",   -- A b C d E F
50        "1111111", "0111111", "0101111");                        -- blank - r
51
52    signal jp   : std_logic;                                 -- 1 = jackpot (counter mode and value 777)
53begin
54    -- counter : change the value only at the moment a button is pressed (1 -> 0)
55    s1 <= 1 when SW(1) = '0' else 5;     -- step of button1 (+) and button3 (-)
56    s2 <= 2 when SW(1) = '0' else 10;    -- step of button2 (+)
57
58    process (CLOCK_50)
59    begin
60        if rising_edge(CLOCK_50) then
61            k1 <= KEY;
62            k2 <= k1;
63            if SW(0) = '0' then          -- counter mode only
64                if k2(0) = '1' and k1(0) = '0' then          -- KEY0 : reset
65                    cnt <= 0;
66                elsif k2(3) = '1' and k1(3) = '0' then       -- KEY3 : up by s1
67                    if cnt + s1 > 9999 then cnt <= 9999; else cnt <= cnt + s1; end if;
68                elsif k2(2) = '1' and k1(2) = '0' then       -- KEY2 : up by s2
69                    if cnt + s2 > 9999 then cnt <= 9999; else cnt <= cnt + s2; end if;
70                elsif k2(1) = '1' and k1(1) = '0' then       -- KEY1 : down by s1
71                    if cnt < s1 then cnt <= 0; else cnt <= cnt - s1; end if;
72                end if;
73            end if;
74        end if;
75    end process;
76
77    -- LEDs (counter mode only) : red = value in binary, jackpot at 777 : green all on
78    jp   <= '1' when SW(0) = '0' and cnt = 777 else '0';
79    LEDR <= std_logic_vector(to_unsigned(cnt, 18)) when SW(0) = '0' else (others => '0');
80    LEDG <= (others => jp);
81
82    -- calculator : 00 add, 01 subtract, 10 multiply, 11 divide
83    a      <= to_integer(unsigned(SW(17 downto 14)));
84    b      <= to_integer(unsigned(SW(13 downto 10)));
85    base   <= 16 when SW(3) = '1' else 10;
86    valid  <= '1' when SW(3) = '1' or (a < 10 and b < 10) else '0';
87    result <= a + b      when SW(2 downto 1) = "00" else
88              abs(a - b) when SW(2 downto 1) = "01" else     -- subtract : absolute value, the sign '-' is added when a < b
89              a * b;
90
91    -- decide what each 7-segment shows
92    process (SW, cnt, a, b, base, result, valid)
93    begin
94        d <= (others => BLANK);          -- everything off first
95
96        if SW(0) = '0' then              -- counter : thousands, hundreds, tens, ones
97            d(3) <= cnt / 1000;
98            d(2) <= (cnt / 100) mod 10;
99            d(1) <= (cnt / 10) mod 10;
100            d(0) <= cnt mod 10;
101            if cnt = 777 then d(7 downto 4) <= (others => 7); end if;   -- jackpot : show 7777
102        else                             -- calculator
103            if SW(3) = '1' or a < 10 then d(6) <= a; end if;   -- decimal mode shows 0~9 only
104            if SW(3) = '1' or b < 10 then d(4) <= b; end if;
105            if valid = '1' then
106                if SW(2 downto 1) /= "11" then               -- + - * : 2 digits (decimal 81 at most, hexadecimal E1 at most)
107                    if SW(2 downto 1) = "01" and a < b then d(3) <= MINUS; end if;   -- MINUS = code 17 = '-' (d(3) is an integer code, not a character)
108                    d(1) <= result / base;
109                    d(0) <= result mod base;
110                elsif b = 0 then                             -- divide by zero : " Err"
111                    d(2) <= CH_E;  d(1) <= CH_R;  d(0) <= CH_R;
112                else                                         -- division : "quotient r remainder"
113                    d(3) <= a / b;  d(1) <= CH_R;  d(0) <= a mod b;
114                end if;
115            end if;
116        end if;
117    end process;
118
119    HEX0 <= SEG7(d(0));  HEX1 <= SEG7(d(1));  HEX2 <= SEG7(d(2));  HEX3 <= SEG7(d(3));
120    HEX4 <= SEG7(d(4));  HEX5 <= SEG7(d(5));  HEX6 <= SEG7(d(6));  HEX7 <= SEG7(d(7));
121end behavior;

발표 예상 질문

코드를 보지 않고 답해 보면 좋은 질문.

버튼을 길게 눌러도 왜 한 번만 오르나?

48~49줄에서 버튼을 두 클럭에 걸쳐 저장하고, 50~57줄이 k2='1' and k1='0'(1→0으로 바뀐 순간)에만 값을 바꾼다. 누르고 있는 동안은 k2와 k1이 모두 0이라 조건이 거짓이다.

뺄셈이 음수면 어떻게 처리하나?

72~74줄에서 abs(a - b)로 큰 수에서 작은 수를 뺀 절댓값을 result에 넣는다. 표시 단계(91줄)가 a < b이면 HEX3에 '-'를 붙인다.

나머지는 어떻게 구하나?

97줄: 몫은 a / b, 나머지는 a mod b로 구한다. 0으로 나누는 경우는 94줄에서 먼저 걸러 낸다.

16진수 결과는 어떻게 두 자리로 나누나?

92~93줄: 결과를 base(16)로 나눈 몫이 HEX1, 나머지가 HEX0. 225는 14와 1이라서 E1이다. 십진수 모드에서는 base가 10이라 같은 두 줄이 십의 자리와 일의 자리를 만든다.

동시에 버튼 두 개를 누르면?

50~57줄이 elsif 체인이라 KEY0 > KEY3 > KEY2 > KEY1 순서로 하나만 적용되지만, 이것은 두 눌림이 같은 클럭(20 ns)에 겹칠 때만이다. 손으로 누르면 몇 ms 어긋나서 두 에지가 따로 잡혀 둘 다 적용된다. 예) KEY3과 KEY2를 거의 동시에 누르면 +1 후 +2로 +3, KEY3을 먼저 누르고 KEY0을 누르면 0, KEY0을 먼저 누르고 KEY3을 누르면 1(보드에서 확인). 동시 입력에 대한 규칙은 과제에 따로 없다.

777일 때 LEDR의 이진수 표시는 어떻게 되나?

65~66줄: 잭팟이어도 LEDR은 계속 이진수(777 = 1100001001)를 보여 주고, 초록 LED(LEDG)가 모두 켜져 있다.

integer와 unsigned는 왜 나눠 쓰나?

integer는 범위만 정하면 되는 숫자라서 계산과 비교(/, mod, >)에 쓴다(cnt, a, b). unsigned는 비트 묶음을 음수 없는 숫자로 보는 타입이라 스위치 비트를 숫자로 바꿀 때(to_integer(unsigned(SW(17 downto 14)))) 쓴다.

mod 10은 무슨 뜻인가?

10으로 나눈 나머지, 즉 십진수의 마지막 자리다. cnt mod 10이 일의 자리, (cnt / 10) mod 10이 십의 자리다.

MINUS를 놔두고 '-'를 쓰면 안 되나?

d(3)는 문자 코드(정수 0~18)를 담는 칸이라서 문자 '-'를 넣을 수 없다. MINUS는 코드 17이고, 7세그 표 17번 칸이 '-' 모양이다.

HEX7~4에 7777은 왜 띄우나?

카운터 모드에서 쓰지 않는 왼쪽 네 칸을 잭팟 연출에 쓴다. 777일 때만 d(7 downto 4)를 7로 덮어쓴다(85줄).

d <= (others => BLANK)는 무슨 뜻인가?

78줄: 배열 d의 8칸을 전부 BLANK로 채운다. others는 '나머지 전부'다. 이 아래에서 필요한 칸만 다시 대입하는데, 같은 process 안에서는 마지막 대입이 이긴다.

알아둘 점

  • 시뮬레이션(ModelSim)에서 카운터, 계산기 전 조합, 잭팟 LED 유지를 2129개 검사해 통과했다. 보드 동작은 확인하지 않았다.
  • Quartus Analysis & Synthesis(quartus_map)는 통과했다(오류 0). 배치·배선, 타이밍, 보드 동작은 확인하지 않았다.
  • 십진수 결과는 두 자리로 보인다(예: 7 → 07). 결과가 최대 81이라 세 번째 자리가 항상 0이어서 뺐다. 16진수 결과는 원래 두 자리였다.
