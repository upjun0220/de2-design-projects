DE2 Design Project #1 — 줄별 설명

카운터 + 한 자리 계산기 (보너스 포함) · design1/src/DE2_Project1.vhd 80줄 · 발표 준비용

머리말 주석라이브러리와 입출력 핀선언부 — 상수, 표, 신호카운터LED와 잭팟 판정계산기7세그 표시 결정출력 연결주석이 있던 원본예상 질문알아둘 점
전체 흐름
  1. 입력: 스위치 SW와 버튼 KEY를 읽는다. SW0이 카운터/계산기를 고른다.
  2. 카운터 모드: 버튼을 누르는 순간 cnt가 바뀐다(0~9999). 계산기 모드: 스위치 값으로 매번 다시 계산한다.
  3. 표시: 결과를 문자 코드로 바꿔 7세그(HEX)와 LED(LEDR/LEDG)에 내보낸다. 777이면 잭팟 효과가 나온다.

머리말 주석

코드에서는 지웠고, 사용법을 요약해 둔 주석이었다. 원문을 그대로 보여 준다.

코드에서 삭제한 주석 (원문)
-- DE2 Design Project #1 : Counter + One Digit Calculator (with bonus)
과제 이름과 보너스 포함 여부. --로 시작하는 줄은 주석이라 회로에 영향이 없다.
코드에서 삭제한 주석 (원문)
-- SW0 : 0 = counter, 1 = calculator
SW0이 카운터/계산기를 고르는 스위치다. 0이면 카운터, 1이면 계산기.
코드에서 삭제한 주석 (원문)
-- Counter    : SW1 = mode, KEY3/KEY2/KEY1 = change value, KEY0 = reset
--              HEX3~0 = value, LEDR = value in binary
--              jackpot at 777 : green LEDs stay on, HEX7~4 show 7777
카운터 모드 요약. SW1은 증감 크기를 고르고(0: +1/+2/-1, 1: +5/+10/-5), KEY3/KEY2/KEY1이 값을 바꾸고 KEY0이 0으로 리셋한다. 값은 HEX3~0에 십진수로, LEDR에 이진수로 나온다. 값이 777이면 잭팟(초록 LED가 켜진 채 유지, HEX7~4에 7777).
코드에서 삭제한 주석 (원문)
-- Calculator : SW17~14 = A, SW13~10 = B, SW2~1 = operation (00 +, 01 -, 10 *, 11 /)
--              SW3 = 0 : decimal (A, B = 0~9),  SW3 = 1 : hexadecimal (0~F)
--              A on HEX6, B on HEX4, result on HEX3~0
--              division shows "quotient r remainder", for example 7 / 3 -> "2 r1"
계산기 모드 요약. A는 SW17~14, B는 SW13~10(각 4비트), 연산은 SW2~1(00 덧셈, 01 뺄셈, 10 곱셈, 11 나눗셈). SW3=0이면 십진수(A, B는 0~9), 1이면 16진수(0~F). A는 HEX6, B는 HEX4, 결과는 HEX3~0. 나눗셈은 몫 r 나머지 형태.

카운터

버튼을 누르는 순간 한 번만 값이 바뀌고 0~9999에서 멈춘다.

38줄
38    ed <= k2 and not k1;
버튼 에지 검출. k2 and not k1은 비트마다 'k2=1이고 k1=0'을 계산한다. 그래서 ed(i)가 1이면 KEY i가 방금 눌렸다(1→0)는 뜻이다. 길게 눌러도 ed가 1인 것은 한 클럭뿐이라 한 번만 센다.
39줄
39    s  <= 1 when SW(1) = '0' else 5;
증감 크기. when ... else는 조건에 따라 값을 고르는 대입문이다. SW1=0이면 s=1, SW1=1이면 5. KEY3(+s)과 KEY1(-s)이 s를, KEY2는 그 두 배(2 또는 10)를 쓴다.
40~41줄
40    n  <= cnt when SW(0) = '1' else 0 when ed(0) = '1' else cnt + s when ed(3) = '1' else
41          cnt + 2 * s when ed(2) = '1' else cnt - s when ed(1) = '1' else cnt;
다음 값 n. when ... else는 위에서부터 차례로 검사하므로 우선순위는 계산기 모드(값 유지) > KEY0(리셋) > KEY3(+s) > KEY2(+2s) > KEY1(-s)이고, 아무것도 아니면 그대로(cnt)다. 이 우선순위는 두 에지가 같은 클럭(20 ns)에 겹칠 때만 의미가 있다. 손으로 누르면 보통 몇 ms 어긋나서 두 에지가 따로 잡히고, 나중에 잡힌 쪽이 마지막에 반영된다.
43~44줄
43    process (CLOCK_50)
44    begin
process (CLOCK_50): 클럭 신호가 바뀔 때 실행되는 블록.
45줄
45        if rising_edge(CLOCK_50) then
rising_edge: 클럭이 0→1로 올라가는 순간에만 안쪽을 실행한다(동기 회로).
46줄
46            k1 <= KEY;  k2 <= k1;
버튼을 두 단계로 저장한다. 매 클럭 k1=지금 KEY, k2=한 클럭 전 k1. 위의 ed 계산에 쓰인다.
47줄
47            if n < 0 then cnt <= 0; elsif n > 9999 then cnt <= 9999; else cnt <= n; end if;
n을 cnt에 넣되 0보다 작으면 0, 9999보다 크면 9999에 고정(포화)한다. 계산기 모드에서는 n=cnt라 값이 그대로다.
48~49줄
48        end if;
49    end process;
열려 있던 if와 process를 닫는다.

LED와 잭팟 판정

빨간 LED는 항상 이진수 표시, 777이면 초록 LED가 모두 켜진 채 유지된다.

51줄
51    LEDR <= std_logic_vector(to_unsigned(cnt, 18)) when SW(0) = '0' else (others => '0');
LEDR: 카운터 모드이면 cnt를 18비트 이진수로 바꿔 출력한다(최대 9999는 14비트라 위 4개는 0). 잭팟(777)일 때도 똑같이 이진수를 보여 준다. 계산기 모드면 전부 0.
52줄
52    LEDG <= (others => '1') when SW(0) = '0' and cnt = 777 else (others => '0');
LEDG: 카운터 모드이고 값이 777이면 8개가 모두 1(켜짐), 아니면 모두 0(꺼짐). 깜빡이지 않고 켜진 채 유지된다. (others => '1')은 모든 비트를 같은 값으로 채운다는 뜻이다.

계산기

스위치 값이 바뀔 때마다 다시 계산하는 조합 회로다.

54~55줄
54    a    <= to_integer(unsigned(SW(17 downto 14)));
55    b    <= to_integer(unsigned(SW(13 downto 10)));
SW(17 downto 14)를 unsigned로 보고 to_integer로 정수 0~15를 만든다. 이것이 A, 같은 식으로 SW13~10이 B.
56줄
56    base <= 16 when SW(3) = '1' else 10;
16진수 모드(SW3=1)이면 base=16, 아니면 10.
57줄
57    res  <= a + b when SW(2 downto 1) = "00" else abs(a - b) when SW(2 downto 1) = "01" else a * b;
연산 결과. 연산(SW2~1)에 따라 when ... else로 고른다. 00 덧셈, 01 뺄셈, 그 밖에는 곱셈. 뺄셈은 abs(a - b)로 큰 수에서 작은 수를 뺀 절댓값을 구하고, 음수 기호는 표시 단계에서 a < b일 때 붙인다. 나눗셈(11)은 표시 단계에서 직접 계산하므로 여기 값은 쓰지 않는다.

7세그 표시 결정

각 HEX에 무엇을 보일지 문자 코드(d(0)~d(7))로 정한다.

59~60줄
59    process (SW, cnt, a, b, base, res)
60    begin
표시 내용을 정하는 process. 값이 바뀌면 다시 계산하는 조합 회로.
61줄
61        d <= (others => BLANK);
먼저 8칸 모두 빈칸으로 둔다. (others => BLANK)는 배열의 모든 칸을 한 값으로 채운다는 뜻이다. 아래에서 필요한 칸만 덮어쓴다.
62줄
62        if SW(0) = '0' then
카운터 모드.
63줄
63            for i in 0 to 3 loop d(i) <= (cnt / 10 ** i) mod 10; end loop;
값을 자릿수로 쪼갠다. i번째 자리는 (cnt / 10 ** i) mod 10이다. 10 ** i는 10의 i제곱(1, 10, 100, 1000)이라 i=0이 일의 자리(HEX0), i=3이 천의 자리(HEX3)다. 예) 1234, i=2 → 1234/100=12, 12 mod 10=2. for 반복문은 합성할 때 4줄로 펼쳐진다.
64줄
64            if cnt = 777 then d(7 downto 4) <= (others => 7); end if;
잭팟(777)이면 HEX7~4에 7을 4개 띄운다. d(7 downto 4)는 배열의 네 칸을 한꺼번에 가리킨다.
65줄
65        elsif a < base and b < base then
계산기 모드. 단, 십진수 모드(base = 10)에서 A나 B가 10 이상이면 거짓이 되어 아무 것도 쓰지 않으므로 61줄의 기본값대로 표시가 모두 꺼진다. 한 자리 십진수는 0~9이기 때문이다. 16진수 모드는 base = 16이라 0~15가 항상 통과한다.
66줄
66            d(6) <= a;  d(4) <= b;
A는 HEX6, B는 HEX4에 표시.
67줄
67            if SW(2 downto 1) /= "11" then
/=는 '같지 않다'. 나눗셈이 아닌 연산(+, -, ×)이면 아래 두 단계로 표시한다.
68줄
68                if SW(2 downto 1) = "01" and a < b then d(3) <= MINUS; end if;
뺄셈에서 A가 B보다 작으면 결과가 음수이므로 HEX3에 '-'.
69줄
69                d(1) <= res / base;  d(0) <= res mod base;
결과를 base로 나눈 몫이 HEX1, 나머지가 HEX0이다. 16진수 모드는 16으로 나눠 225 → E1, 십진수 모드는 10으로 나눠 십의 자리와 일의 자리가 된다(최대 81).
70~71줄
70            elsif b = 0 then
71                d(2) <= CH_E;  d(1) <= CH_R;  d(0) <= CH_R;
0으로 나눔: HEX2~0에 ' Err'(E, r, r).
72~73줄
72            else
73                d(3) <= a / b;  d(1) <= CH_R;  d(0) <= a mod b;
나눗셈: HEX3=몫, HEX1='r', HEX0=나머지. 예) 7÷3 → 2 r1. 이 줄은 B≠0일 때만 실행되므로 0으로 나누는 일이 없다.
74~76줄
74            end if;
75        end if;
76    end process;
열려 있던 if들과 process를 닫는다.

주석이 있던 원본

저장소의 코드에는 주석이 없다. 지운 주석을 포함한 원본(97줄)이다.

펼치기
1-- DE2 Design Project #1 : Counter + One Digit Calculator (with bonus)
2-- SW0 : 0 = counter, 1 = calculator
3-- Counter    : SW1 = mode, KEY3/KEY2/KEY1 = change value, KEY0 = reset
4--              HEX3~0 = value, LEDR = value in binary
5--              jackpot at 777 : green LEDs stay on, HEX7~4 show 7777
6-- Calculator : SW17~14 = A, SW13~10 = B, SW2~1 = operation (00 +, 01 -, 10 *, 11 /)
7--              SW3 = 0 : decimal (A, B = 0~9),  SW3 = 1 : hexadecimal (0~F)
8--              A on HEX6, B on HEX4, result on HEX3~0
9--              division shows "quotient r remainder", for example 7 / 3 -> "2 r1"
10library ieee;
11use ieee.std_logic_1164.all;
12use ieee.numeric_std.all;
13
14entity DE2_Project1 is
15    port (CLOCK_50 : in  std_logic;
16          KEY      : in  std_logic_vector(3 downto 0);
17          SW       : in  std_logic_vector(17 downto 0);
18          LEDR     : out std_logic_vector(17 downto 0);
19          LEDG     : out std_logic_vector(7 downto 0);
20          HEX0, HEX1, HEX2, HEX3, HEX4, HEX5, HEX6, HEX7 : out std_logic_vector(6 downto 0));
21end DE2_Project1;
22
23architecture behavior of DE2_Project1 is
24    -- character codes : 0~15 = hex digit 0~F, 16 = blank, 17 = '-', 18 = 'r'
25    constant BLANK : integer := 16;
26    constant MINUS : integer := 17;
27    constant CH_R  : integer := 18;
28    constant CH_E  : integer := 14;   -- same shape as hex E
29
30    -- 7-segment pattern of each character code (a segment lights up when 0)
31    type seg_table is array (0 to 18) of std_logic_vector(6 downto 0);
32    constant SEG7 : seg_table := (
33        "1000000", "1111001", "0100100", "0110000", "0011001",   -- 0 1 2 3 4
34        "0010010", "0000010", "1111000", "0000000", "0010000",   -- 5 6 7 8 9
35        "0001000", "0000011", "1000110", "0100001", "0000110", "0001110",   -- A b C d E F
36        "1111111", "0111111", "0101111");                        -- blank - r
37
38    -- what each 7-segment shows : d(0) is HEX0, ..., d(7) is HEX7
39    type digits is array (7 downto 0) of integer range 0 to 18;
40    signal d      : digits;
41    signal k1, k2 : std_logic_vector(3 downto 0) := "1111";  -- buttons now / one clock ago
42    signal ed     : std_logic_vector(3 downto 0);            -- 1 = button just pressed (1 -> 0)
43    signal cnt    : integer range 0 to 9999 := 0;            -- counter value
44    signal n      : integer range -5 to 10009;               -- next counter value, before the 0~9999 limit
45    signal s      : integer range 1 to 5;                    -- step size
46    signal a, b   : integer range 0 to 15;                   -- calculator inputs
47    signal base   : integer range 10 to 16;                  -- number base of the result : 10 or 16
48    signal res    : integer range 0 to 255;                  -- result of + - * (absolute value)
49begin
50    -- counter : change the value only at the moment a button is pressed (1 -> 0)
51    ed <= k2 and not k1;
52    s  <= 1 when SW(1) = '0' else 5;    -- step of KEY3 and KEY1 (KEY2 uses twice that)
53    -- next value : calculator mode keeps it, then by priority KEY0 reset, KEY3 up by s, KEY2 up by 2s, KEY1 down by s
54    n  <= cnt when SW(0) = '1' else 0 when ed(0) = '1' else cnt + s when ed(3) = '1' else
55          cnt + 2 * s when ed(2) = '1' else cnt - s when ed(1) = '1' else cnt;
56
57    process (CLOCK_50)
58    begin
59        if rising_edge(CLOCK_50) then
60            k1 <= KEY;  k2 <= k1;
61            if n < 0 then cnt <= 0; elsif n > 9999 then cnt <= 9999; else cnt <= n; end if;   -- stop at 0 and 9999
62        end if;
63    end process;
64
65    -- LEDs (counter mode only) : red = value in binary, jackpot at 777 : green all on
66    LEDR <= std_logic_vector(to_unsigned(cnt, 18)) when SW(0) = '0' else (others => '0');
67    LEDG <= (others => '1') when SW(0) = '0' and cnt = 777 else (others => '0');
68
69    -- calculator : 00 add, 01 subtract, 10 multiply, 11 divide
70    a    <= to_integer(unsigned(SW(17 downto 14)));
71    b    <= to_integer(unsigned(SW(13 downto 10)));
72    base <= 16 when SW(3) = '1' else 10;
73    res  <= a + b when SW(2 downto 1) = "00" else abs(a - b) when SW(2 downto 1) = "01" else a * b;
74
75    -- decide what each 7-segment shows
76    process (SW, cnt, a, b, base, res)
77    begin
78        d <= (others => BLANK);          -- everything off first
79        if SW(0) = '0' then              -- counter : thousands, hundreds, tens, ones
80            for i in 0 to 3 loop d(i) <= (cnt / 10 ** i) mod 10; end loop;
81            if cnt = 777 then d(7 downto 4) <= (others => 7); end if;   -- jackpot : show 7777
82        elsif a < base and b < base then   -- calculator (decimal mode : all blank if A or B is 10 or more)
83            d(6) <= a;  d(4) <= b;
84            if SW(2 downto 1) /= "11" then                   -- + - * : 2 digits
85                if SW(2 downto 1) = "01" and a < b then d(3) <= MINUS; end if;   -- MINUS = code 17 = '-' (d(3) is an integer code, not a character)
86                d(1) <= res / base;  d(0) <= res mod base;
87            elsif b = 0 then                                 -- divide by zero : " Err"
88                d(2) <= CH_E;  d(1) <= CH_R;  d(0) <= CH_R;
89            else                                             -- division : "quotient r remainder"
90                d(3) <= a / b;  d(1) <= CH_R;  d(0) <= a mod b;
91            end if;
92        end if;
93    end process;
94
95    HEX0 <= SEG7(d(0));  HEX1 <= SEG7(d(1));  HEX2 <= SEG7(d(2));  HEX3 <= SEG7(d(3));
96    HEX4 <= SEG7(d(4));  HEX5 <= SEG7(d(5));  HEX6 <= SEG7(d(6));  HEX7 <= SEG7(d(7));
97end behavior;

발표 예상 질문

코드를 보지 않고 답해 보면 좋은 질문.

버튼을 길게 눌러도 왜 한 번만 오르나?

38줄의 ed는 k2가 1이고 k1이 0인 순간(1→0으로 바뀐 때)에만 1이다. 누르고 있는 동안은 k2와 k1이 모두 0이라 ed=0이고, 40~41줄의 n은 값을 그대로 둔다.

뺄셈이 음수면 어떻게 처리하나?

57줄에서 abs(a - b)로 큰 수에서 작은 수를 뺀 절댓값을 res에 넣는다. 표시 단계(68줄)가 a < b이면 HEX3에 '-'를 붙인다.

나머지는 어떻게 구하나?

73줄: 몫은 a / b, 나머지는 a mod b로 구한다. 0으로 나누는 경우는 70줄에서 먼저 걸러 낸다.

16진수 결과는 어떻게 두 자리로 나누나?

69줄: 결과를 base(16)로 나눈 몫이 HEX1, 나머지가 HEX0. 225는 14와 1이라서 E1이다. 십진수 모드에서는 base가 10이라 같은 줄이 십의 자리와 일의 자리를 만든다.

동시에 버튼 두 개를 누르면?

40~41줄의 when ... else 체인이 위에서부터 하나만 고르므로 KEY0 > KEY3 > KEY2 > KEY1 순서로 하나만 적용되지만, 이것은 두 눌림이 같은 클럭(20 ns)에 겹칠 때만이다. 손으로 누르면 몇 ms 어긋나서 두 에지가 따로 잡혀 둘 다 적용된다. 예) KEY3과 KEY2를 거의 동시에 누르면 +1 후 +2로 +3, KEY3을 먼저 누르고 KEY0을 누르면 0, KEY0을 먼저 누르고 KEY3을 누르면 1(보드에서 확인). 동시 입력에 대한 규칙은 과제에 따로 없다.

777일 때 LEDR의 이진수 표시는 어떻게 되나?

51~52줄: 잭팟이어도 LEDR은 계속 이진수(777 = 1100001001)를 보여 주고, 초록 LED(LEDG)가 모두 켜져 있다.

integer와 unsigned는 왜 나눠 쓰나?

integer는 범위만 정하면 되는 숫자라서 계산과 비교(/, mod, >)에 쓴다(cnt, a, b). unsigned는 비트 묶음을 음수 없는 숫자로 보는 타입이라 스위치 비트를 숫자로 바꿀 때(to_integer(unsigned(SW(17 downto 14)))) 쓴다.

mod 10은 무슨 뜻인가?

10으로 나눈 나머지, 즉 십진수의 마지막 자리다. cnt mod 10이 일의 자리, (cnt / 10) mod 10이 십의 자리다.

MINUS를 놔두고 '-'를 쓰면 안 되나?

d(3)는 문자 코드(정수 0~18)를 담는 칸이라서 문자 '-'를 넣을 수 없다. MINUS는 코드 17이고, 7세그 표 17번 칸이 '-' 모양이다.

HEX7~4에 7777은 왜 띄우나?

카운터 모드에서 쓰지 않는 왼쪽 네 칸을 잭팟 연출에 쓴다. 777일 때만 d(7 downto 4)를 7로 덮어쓴다(64줄).

d <= (others => BLANK)는 무슨 뜻인가?

61줄: 배열 d의 8칸을 전부 BLANK로 채운다. others는 '나머지 전부'다. 이 아래에서 필요한 칸만 다시 대입하는데, 같은 process 안에서는 마지막 대입이 이긴다.

10 ** i는 무슨 뜻인가?

63줄: **는 거듭제곱이라 10의 i제곱이다. 1, 10, 100, 1000으로 나눈 뒤 10으로 나눈 나머지를 취하면 일, 십, 백, 천의 자리가 된다.

십진수 모드에서 A나 B에 10 이상을 넣으면?

계산기 표시(A, B, 결과)가 모두 꺼진다. 65줄 elsif a < base and b < base then이 거짓이면 아무 것도 쓰지 않아 61줄의 빈칸 기본값이 남는다. 한 자리 십진수는 0~9이기 때문이다. 0~F를 쓰려면 SW3을 1로 올려 16진수 모드로 바꾼다.

알아둘 점

  • 시뮬레이션(ModelSim)에서 카운터, 계산기 전 조합(십진수 0~9, 16진수 0~F, 십진수 모드의 10 이상 입력은 표시 꺼짐), 잭팟 LED 유지를 2129개 검사해 통과했다. 보드 동작은 확인하지 않았다.
  • Quartus Analysis & Synthesis(quartus_map)는 통과했다(오류 0). 배치·배선, 타이밍, 보드 동작은 확인하지 않았다.
  • 십진수 모드에서 A나 B가 10 이상이면 계산기 표시를 모두 끈다(65줄). else를 elsif로 바꾼 것이라 줄 수는 그대로다.
  • 십진수 결과는 두 자리로 보인다(예: 7 → 07). 결과가 최대 81이라 세 번째 자리가 항상 0이어서 뺐다. 16진수 결과는 원래 두 자리였다.
