DE2 Design Project #1 — 줄별 설명

카운터 + 한 자리 계산기 (보너스 포함) · design1/src/DE2_Project1.vhd 188줄 · 발표 준비용

머리말 주석라이브러리와 입출력 핀선언부 — 상수, 신호, 표카운터LED와 잭팟 판정계산기7세그 표시 결정LCD 출력출력 연결예상 질문알아둘 점
전체 흐름
  1. 입력: 스위치 SW와 버튼 KEY를 읽는다. SW0이 카운터/계산기를 고른다.
  2. 카운터 모드: 버튼을 누르는 순간 cnt가 바뀐다(0~9999). 계산기 모드: 스위치 값으로 매번 다시 계산한다.
  3. 표시: 결과를 문자 코드로 바꿔 7세그(HEX), LED(LEDR/LEDG), LCD에 내보낸다. 777이면 잭팟 효과가 나온다.

머리말 주석

회로에는 영향이 없고 사용법을 적어 둔 부분이다.

1줄
1-- DE2 Design Project #1 : Counter + One Digit Calculator (with bonus)
과제 이름과 보너스 포함 여부. --로 시작하는 줄은 주석이라 회로에 영향이 없다.
2줄
2-- SW0 : 0 = counter, 1 = calculator
SW0이 카운터/계산기를 고르는 스위치다. 0이면 카운터, 1이면 계산기.
3~5줄
3-- Counter    : SW1 = mode, KEY3/KEY2/KEY1 = change value, KEY0 = reset
4--              HEX3~0 = value, LEDR = value in binary
5--              jackpot at 777 : red and green LEDs flash, HEX7~4 show 7777
카운터 모드 요약. SW1은 증감 크기를 고르고(0: +1/+2/-1, 1: +5/+10/-5), KEY3/KEY2/KEY1이 값을 바꾸고 KEY0이 0으로 리셋한다. 값은 HEX3~0에 십진수로, LEDR에 이진수로 나온다. 값이 777이면 잭팟.
6줄
6-- LCD        : shows COUNTER or CALCULATOR (mode of SW0), a congratulation text at the jackpot
16×2 문자 LCD에 모드 이름(COUNTER / CALCULATOR)이 뜨고, 잭팟일 때는 축하 문구가 뜬다.
7~10줄
7-- Calculator : SW17~14 = A, SW13~10 = B, SW2~1 = operation (00 +, 01 -, 10 *, 11 /)
8--              SW3 = 0 : decimal (0~9),  SW3 = 1 : hexadecimal (0~F)
9--              A on HEX6, B on HEX4, result on HEX3~0
10--              division shows "quotient r remainder", for example 7 / 3 -> "2 r1"
계산기 모드 요약. A는 SW17~14, B는 SW13~10(각 4비트), 연산은 SW2~1(00 덧셈, 01 뺄셈, 10 곱셈, 11 나눗셈). SW3=0이면 십진수(0~9), 1이면 16진수(0~F). A는 HEX6, B는 HEX4, 결과는 HEX3~0. 나눗셈은 몫 r 나머지 형태.

카운터

버튼을 누르는 순간 한 번만 값이 바뀌고 0~9999에서 멈춘다.

LED와 잭팟 판정

빨간 LED는 이진수 표시, 777이면 빨강과 초록이 번갈아 번쩍인다.

90~91줄
90    -- LEDs (counter mode only) : red = value in binary, jackpot at 777 : red and green flash by turns
91    jp   <= '1' when SW(0) = '0' and cnt = 777 else '0';
잭팟 판정: 카운터 모드이고 값이 777일 때 jp=1.
92~93줄

93            std_logic_vector(to_unsigned(cnt, 18)) when SW(0) = '0' else (others => '0');
LEDR: 잭팟이면 18개가 모두 tick(23)을 따라 켜졌다 꺼진다(번쩍). 아니고 카운터 모드이면 cnt를 18비트 이진수로 바꿔 출력한다(최대 9999는 14비트라 위 4개는 0). 계산기 모드면 전부 0.

LEDG: 잭팟이면 8개가 not tick(23), 즉 빨강과 반대로 번갈아 켜진다. 아니면 꺼진다.

103    begin

104        result <= 0;
105        quot <= 0;
106        remain <= 0;
107        neg <= '0';
먼저 모든 결과를 기본값으로 둔다. 어떤 경우에도 값이 정해지므로 불필요한 래치가 생기지 않는다.
108줄
108        case SW(2 downto 1) is

109줄
109            when "00" => result <= a + b;
00 덧셈.
110~116줄

LCD 출력

HD44780 계열 16×2 문자 LCD에 2.6 ms마다 바이트 하나씩 보낸다.

163~165줄
163    -- LCD (16x2, HD44780, 8 bit bus, write only) : one byte per 2^17 clocks (2.6 ms), sent in a loop
164    -- step 0~5 function set, 6 display on, 7 entry mode, 8 line 1 address, 9~24 line 1 text,
165    -- 25 line 2 address, 26~41 line 2 text (after step 41 it goes back to step 8)
이 블록이 필요한 이유: LCD는 켜 놓는다고 글자가 나오지 않고, 컨트롤러에 명령과 글자를 바이트 단위로 직접 보내 줘야 한다. 이 프로젝트에는 CPU가 없어서 VHDL이 그 일을 한다. 과제 필수가 아니라 잭팟 연출과 모드 표시를 위해 추가한 부분이며, 지워도 카운터·계산기·LED·7세그는 그대로 동작한다. 바이트 번호는 0~41, 총 42개(초기화 명령 8개 + 줄 이동 2개 + 글자 32개). LCD는 8비트 데이터 선으로 쓰기만 하고(busy 확인 없음) 정해진 시간마다 바이트를 보낸다. 번호별 역할: 0~5 초기화(function set), 6 화면 켜기, 7 입력 방식, 8 1행 시작 위치, 9~24 1행 글자, 25 2행 시작 위치, 26~41 2행 글자. 41 다음은 8로 돌아가 글자를 계속 다시 쓴다(내용이 바뀌면 약 0.1초 안에 반영).
166줄
166    LCD_RW  <= '0';  LCD_ON <= '1';  LCD_BLON <= '1';
RW=0(쓰기 전용), LCD 전원 ON, 백라이트 ON.
167줄
167    LCD_EN  <= '1' when tick(16 downto 15) = "10" else '0';   -- pulse in the 3rd quarter, data is stable then
EN 펄스: 2.6 ms 구간(217 클럭)의 세 번째 4분의 1 동안만 1. tick(16 downto 15) 두 비트는 구간 안에서 00, 01, 10, 11 순서로 바뀌고, "10"이 세 번째다. 데이터는 구간 시작에 이미 정해져 있고, EN이 내려가는 순간(다음 4분의 1이 시작될 때) LCD가 값을 읽어 간다.
168~169줄
168    LCD_RS  <= '1' when step > 8 and step /= 25 else '0';     -- 1 = text, 0 = command
RS: 글자를 보내는 번호(9~24, 26~41)일 때 1, 명령일 때 0.
170~172줄
170    process (step, SW, jp)
171        variable i : integer range 1 to 32;      -- position in the 32 characters of the text
172    begin
보낼 바이트를 고르는 process. 번호(step), 모드(SW), 잭팟(jp)이 바뀌면 다시 계산한다. i는 32글자 중 몇 번째 글자인지.
173~174줄
173        i := 1;
174        if step > 25 then i := step - 9; elsif step > 8 then i := step - 8; end if;
글자 위치 계산. 1행 글자(9~24번)는 번호-8로 1~16, 2행 글자(26~41번)는 번호-9로 17~32.
175줄
175        if    step < 6  then LCD_DATA <= x"38";            -- function set : 8 bit bus, 2 lines (repeated = also the power-up wait)
0~5번: x"38" function set. 0011 1000에서 DL=1(8비트 버스), N=1(2줄 모드, 이 LCD가 16×2라서), 글자 크기 5×8. 같은 명령을 여러 번 보내는 것은 전원 직후 LCD가 준비될 때까지 시간을 벌기 위해서다(function set은 반복해도 부작용이 없다). 별도 타이머 없이 step 박자(2.6 ms)를 그대로 쓴다. 계산상 마지막 x"38"이 시작 후 약 12.5 ms, x"0C"가 약 15 ms 지점이라 규격(약 15 ms 대기)에 아슬아슬하다. 보드에서 LCD가 비면 이 대기를 늘려야 한다.
176줄
176        elsif step = 6  then LCD_DATA <= x"0C";            -- display on, cursor off
6번: x"0C" 화면 켜기, 커서 끔.
177줄
177        elsif step = 7  then LCD_DATA <= x"06";            -- cursor moves right after each character
7번: x"06" 글자를 쓸 때마다 커서가 오른쪽으로 이동.
178줄
178        elsif step = 8  then LCD_DATA <= x"80";            -- go to line 1
8번: x"80" 1행 맨 앞으로.
179줄
179        elsif step = 25 then LCD_DATA <= x"C0";            -- go to line 2
25번: x"C0" 2행 맨 앞으로.
180~182줄
180        elsif jp = '1'        then LCD_DATA <= std_logic_vector(to_unsigned(character'pos(JACKPOT_TXT(i)), 8));
181        elsif SW(0) = '0'     then LCD_DATA <= std_logic_vector(to_unsigned(character'pos(COUNTER_TXT(i)), 8));
182        else                       LCD_DATA <= std_logic_vector(to_unsigned(character'pos(CALC_TXT(i)), 8));
글자 번호이면 문구의 i번째 글자의 ASCII 코드(character'pos)를 보낸다. 우선순위는 잭팟 문구 > 카운터 문구 > 계산기 문구.
183~185줄
183        end if;
184    end process;
if와 process를 닫는다.

발표 예상 질문

코드를 보지 않고 답해 보면 좋은 질문.

버튼을 길게 눌러도 왜 한 번만 오르나?

70~71줄에서 버튼을 두 클럭에 걸쳐 저장하고, 77~84줄이 k2='1' and k1='0'(1→0으로 바뀐 순간)에만 값을 바꾼다. 누르고 있는 동안은 k2와 k1이 모두 0이라 조건이 거짓이다.

뺄셈이 음수면 어떻게 처리하나?

110~116줄에서 큰 수에서 작은 수를 빼서 result에 절댓값을 넣고 neg를 1로 둔다. 표시 단계(148~149줄)가 HEX3에 '-'를 붙인다.

나머지는 어떻게 구하나?

118~122줄: 몫은 a / b, 나머지는 a mod b로 구한다.

16진수 결과는 어떻게 두 자리로 나누나?

150~152줄: 결과를 16으로 나눈 몫이 HEX1, 나머지가 HEX0. 225는 14와 1이라서 E1이다.

동시에 버튼 두 개를 누르면?

77~84줄이 elsif 체인이라 KEY0 > KEY3 > KEY2 > KEY1 순서로 하나만 적용된다.

777일 때 LEDR의 이진수 표시는 어떻게 되나?

92~93줄에서 잭팟이면 이진수 대신 tick(23)을 따라 전체가 깜빡인다. 잭팟이 끝나면 다시 이진수로 돌아온다.

LCD는 왜 busy 상태를 읽지 않나?

코드를 짧게 하려고 바이트마다 약 2.6 ms를 기다리는 고정 시간 방식을 썼다. 실제 LCD에서의 동작은 보드에서 확인해야 한다.

LCD 코드(163~184줄)는 왜 필요하고, 지워도 되나?

LCD는 FPGA가 명령과 글자를 바이트 단위로 보내 줘야 글자가 나온다. 과제 필수가 아니라 잭팟 문구와 모드 표시를 위한 추가 기능이다. 지워도 나머지 기능은 그대로 동작하지만, 우리는 유지하기로 했다.

LCD를 왜 2줄로 설정하나?

175줄의 x"38"에서 N 비트가 1이면 2줄 모드다. DE2의 LCD가 16×2라서 2행도 써야 하고, 그래서 문구가 16글자 + 16글자인 32글자다. 1줄 모드(x"30")면 2행 글자가 안 나온다. (HD44780 일반 규격 기준, 이 보드의 데이터시트와는 대조하지 않았다.)

x"38"을 여러 번 보내는 이유는?

전원 직후 LCD가 준비될 때까지 시간을 벌기 위해서다. function set은 반복해도 안전하고, step 박자(2.6 ms)를 그대로 대기 시간으로 쓴다. 다만 계산상 약 12.5~15 ms라 규격에 아슬아슬해서, 보드에서 LCD가 비면 이 구간을 늘려야 한다.

EN 신호는 왜 tick(16 downto 15) = "10"인가?

2.6 ms 구간을 4등분하면 이 두 비트가 00, 01, 10, 11로 바뀐다. 세 번째 구간에서 EN을 1로 올리면, 데이터가 이미 안정된 뒤에 EN이 내려가며 LCD가 값을 읽는다.

바이트 번호가 왜 41까지인가?

LCD에 보내는 바이트가 초기화 명령 8개, 줄 이동 2개, 글자 32개로 총 42개라서 0~41이다. 41 다음은 초기화를 건너뛰고 8번으로 돌아가 글자만 계속 다시 쓴다.

왜 문구를 32글자로 만드나?

16×2 LCD는 칸이 32개라서 문구를 칸 수에 맞춘다. 2행을 공백으로 채워 두어야 잭팟이 끝났을 때 이전 축하 문구가 지워진다.

integer와 unsigned는 왜 나눠 쓰나?

integer는 범위만 정하면 되는 숫자라서 계산과 비교(/, mod, >)에 쓴다(cnt, a, b). unsigned는 비트 묶음을 음수 없는 숫자로 보는 타입이라 한 비트만 꺼내 쓰거나(tick(23)) 스위치 비트를 숫자로 바꿀 때 쓴다.

mod 10은 무슨 뜻인가?

10으로 나눈 나머지, 즉 십진수의 마지막 자리다. cnt mod 10이 일의 자리, (cnt / 10) mod 10이 십의 자리다.

MINUS를 놔두고 '-'를 쓰면 안 되나?

d3는 문자 코드(정수 0~18)를 담는 신호라서 문자 '-'를 넣을 수 없다. MINUS는 코드 17이고, 7세그 표 17번 칸이 '-' 모양이다.

HEX7~4에 7777은 왜 띄우나?

카운터 모드에서 쓰지 않는 왼쪽 네 칸을 잭팟 연출에 쓴다. 777일 때만 d7~d4를 7로 덮어쓴다.

알아둘 점

  • 시뮬레이션(ModelSim)에서 카운터, 계산기 전 조합, LCD 글자, LED 점멸을 2133개 검사해 통과했다. Quartus 합성과 보드 동작은 확인하지 않았다.
  • LCD 핀 번호는 공개 저장소의 DE2용 .qsf 두 곳이 같은 값을 줘서 쓴 것이고, DE2 User Manual 원문과는 대조하지 않았다.
  • Quartus Analysis & Synthesis(quartus_map)는 통과했다(오류 0). 배치·배선, 타이밍, 보드 동작은 확인하지 않았다.
  • LCD 초기화(0~7번)는 전원 직후 한 번만 보내고 이후 루프는 8~41번만 반복한다. 대기가 부족하면 LCD가 빈 채로 남을 수 있으니 보드에서 가장 먼저 확인한다.
