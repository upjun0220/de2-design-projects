1. 한눈에 보기

스위치 SW0 하나로 카운터와 한 자리 계산기를 오가는 회로입니다. 결과는 7세그먼트(HEX)에 표시하고, 보너스로 LED 표시, 777 잭팟, 나눗셈 나머지, 16진수 표시를 넣었습니다.

코드는 크게 세 덩어리로 나뉩니다. 앞의 두 덩어리가 값을 만들고, 세 번째가 화면에 무엇을 띄울지 정합니다.

3. 라이브러리와 포트 (entity)

1library ieee;
2use ieee.std_logic_1164.all;
3use ieee.numeric_std.all;
4
5entity DE2_Project1 is
6    port (CLOCK_50 : in  std_logic;
7          KEY      : in  std_logic_vector(3 downto 0);
8          SW       : in  std_logic_vector(17 downto 0);
9          LEDR     : out std_logic_vector(17 downto 0);
10          LEDG     : out std_logic_vector(7 downto 0);
11          HEX0, HEX1, HEX2, HEX3, HEX4, HEX5, HEX6, HEX7 : out std_logic_vector(6 downto 0));
12end DE2_Project1;
  • library ieee; use ieee.std_logic_1164.all; : 신호 타입 std_logic(0 또는 1 한 비트)을 쓰기 위한 선언입니다.
  • use ieee.numeric_std.all; : 이진수와 정수를 바꾸는 함수(unsigned, to_integer, to_unsigned)를 쓰기 위한 선언입니다.
  • entity는 회로의 겉모습, 즉 입력과 출력 핀 목록입니다. in은 입력, out은 출력입니다.
  • CLOCK_50 : 보드의 50MHz 클럭 (한 클럭 = 20ns). KEY : 버튼 4개. SW : 토글스위치 18개.
  • LEDR(빨강 18개), LEDG(초록 8개) : 보너스용 LED.
  • HEX0~HEX7 : 7세그먼트 8개. 각각 7비트(세그먼트 a~g 일곱 개)입니다.
  • 포트 이름은 DE2 핀 할당 파일의 이름과 똑같아야 합니다. 그래야 코드의 신호가 보드의 실제 핀에 연결됩니다.

4. 선언부 (architecture 앞부분)

14architecture behavior of DE2_Project1 is
15    constant BLANK : integer := 16;
16    constant MINUS : integer := 17;
17    constant CH_R  : integer := 18;
18    constant CH_E  : integer := 14;
27    type digits is array (7 downto 0) of integer range 0 to 18;
28    signal d      : digits;
29    signal k1, k2 : std_logic_vector(3 downto 0) := "1111";
30    signal ed     : std_logic_vector(3 downto 0);
31    signal cnt    : integer range 0 to 9999 := 0;
32    signal n      : integer range -5 to 10009;
33    signal s      : integer range 1 to 5;
34    signal a, b   : integer range 0 to 15;
35    signal base   : integer range 10 to 16;
36    signal res    : integer range 0 to 255;
  • constant : 문자 코드를 이름으로 적어 둔 것입니다. 0~15는 16진수 숫자 0~F 그대로, 16(BLANK)은 빈칸, 17(MINUS)은 -, 18(CH_R)은 r입니다. Err의 E는 16진수 E(14)와 모양이 같아서 CH_E로 14를 씁니다.
  • d : HEX 8칸에 각각 무엇을 띄울지(문자 코드 0~18)를 담는 8칸짜리 배열입니다. d(0)이 HEX0, d(7)이 HEX7입니다.
  • k1, k2 : 버튼 값을 한 클럭, 두 클럭 늦게 저장합니다. 초기값 "1111"인 이유는 버튼이 안 눌린 상태가 1이기 때문입니다.
  • ed : 버튼이 방금 눌렸는지(1→0) 나타내는 4비트입니다.
  • cnt : 카운터 값. integer range 0 to 9999로 범위를 정하면 합성할 때 필요한 비트 수(14비트)로 알아서 만들어집니다.
  • n : 한도(0~9999)를 적용하기 전의 다음 값. 한도를 넘거나 모자랄 수 있어서 범위를 -5 to 10009로 넉넉히 잡았습니다(0에서 5를 빼면 -5, 9999에 10을 더하면 10009).
  • s : 버튼을 한 번 눌렀을 때 바뀌는 기본 크기(1 또는 5).
  • a, b : 계산기 입력(0~15). base : 결과를 보일 진법(10 또는 16). res : 더하기·빼기·곱하기의 결과(항상 0 이상, 부호는 표시 단계에서 따로 붙임).

5. SEG7 표 : 코드 → 7세그 패턴

20    type seg_table is array (0 to 18) of std_logic_vector(6 downto 0);
21    constant SEG7 : seg_table := (
22        "1000000", "1111001", "0100100", "0110000", "0011001",
23        "0010010", "0000010", "1111000", "0000000", "0010000",
24        "0001000", "0000011", "1000110", "0100001", "0000110", "0001110",
25        "1111111", "0111111", "0101111");

7세그먼트의 일곱 획에 이름(a~g)이 있고, 이 표는 문자 코드 번호를 칸 번호로 삼아 어느 획을 켤지(7비트) 알려 줍니다. 표는 type seg_table(길이 19, 한 칸 7비트)로 모양을 정하고 constant SEG7에 값을 채웁니다.

 f   b        패턴 순서 : g f e d c b a  (왼쪽부터)
   g          DE2 보드는 0이면 켜지고 1이면 꺼집니다 (active-low)
 e   c
   d          예) 숫자 0 = "1000000" : g만 끄고 나머지 여섯 획을 켬

6. 카운터

6-1. 증감 크기와 다음 값 정하기

38    ed <= k2 and not k1;
39    s  <= 1 when SW(1) = '0' else 5;
40    n  <= cnt when SW(0) = '1' else 0 when ed(0) = '1' else cnt + s when ed(3) = '1' else
41          cnt + 2 * s when ed(2) = '1' else cnt - s when ed(1) = '1' else cnt;
  • 에지 검출 : ed <= k2 and not k1은 비트마다 "한 클럭 전엔 1(안 눌림), 지금은 0(눌림)"을 계산합니다. 그래서 ed(3)이 1이면 KEY3이 방금 눌렸다는 뜻입니다.
  • 증감 크기 : SW1이 0이면 s = 1, 1이면 5입니다. KEY3은 +s, KEY1은 -s, KEY2는 +2s(2 또는 10)입니다. when ... else는 조건에 따라 값을 고르는 신호 대입입니다.
  • 다음 값 n : when ... else는 위에서부터 차례로 검사하므로 그 순서가 곧 우선순위입니다. 계산기 모드(SW(0) = '1')이면 값을 그대로 두고, 아니면 KEY0(리셋) → KEY3 → KEY2 → KEY1 순이며, 아무 버튼도 아니면 cnt 그대로입니다.

6-2. 버튼을 누른 순간만 감지하기

43    process (CLOCK_50)
44    begin
45        if rising_edge(CLOCK_50) then
46            k1 <= KEY;  k2 <= k1;
47            if n < 0 then cnt <= 0; elsif n > 9999 then cnt <= 9999; else cnt <= n; end if;
48        end if;
49    end process;

왜 필요한가? 버튼을 한 번 누르는 0.1초 동안 50MHz 클럭은 500만 번 돕니다. "눌려 있으면 더한다"고 하면 한 번 눌러도 500만 번 더해집니다. 그래서 "전 클럭엔 안 눌림(1), 지금은 눌림(0)"인 단 한 번만 값이 바뀌게 합니다.

클럭 번호123456
KEY3 (눌림 = 0)110000
k1 (한 클럭 전 값)111000
k2 (두 클럭 전 값)111100
ed(3) = k2 and not k1000100

버튼을 계속 눌러도 ed(3)이 1인 클럭은 딱 한 번(4번)뿐입니다.

  • process (CLOCK_50) + rising_edge(CLOCK_50) : 클럭이 올라가는 순간마다 한 번 실행합니다. 값을 기억하는 회로(플립플롭)가 만들어집니다.
  • k1 <= KEY; k2 <= k1; : 버튼 값을 한 단계씩 밀어 저장합니다. 버튼은 클럭과 상관없이 바뀌는 신호라서 한 번 레지스터에 담아 안정화하는 효과도 있습니다.
  • 상한·하한 : n < 0이면 0, n > 9999이면 9999로 고정하고, 그 외에는 n을 cnt에 넣습니다. 계산기 모드에서는 n = cnt라 값이 그대로입니다. 이때도 k1, k2는 계속 갱신되기 때문에 모드를 바꿀 때 가짜 입력이 생기지 않습니다.
  • 동시에 누르면 : 우선순위는 두 버튼이 같은 클럭(20ns)에 눌릴 때만 적용됩니다. 손으로 누르면 보통 몇 ms 어긋나서 둘 다 따로 인식됩니다.
  • 이 부분은 43~49번 줄입니다.

7. LED와 777 잭팟

51    LEDR <= std_logic_vector(to_unsigned(cnt, 18)) when SW(0) = '0' else (others => '0');
52    LEDG <= (others => '1') when SW(0) = '0' and cnt = 777 else (others => '0');
  • to_unsigned(cnt, 18) : 정수 cnt를 18비트 이진수로 바꿔 LEDR 18개 전체에 연결합니다. 9999는 14비트라 위 4개는 항상 0입니다.
  • (others => '0') : 모든 비트를 0으로 채운다는 뜻입니다. 계산기 모드(SW0 = 1)에서는 LED를 끕니다.
  • LEDG : 카운터 모드에서 cnt = 777이면 초록 LED 8개를 모두 켠 채 유지합니다(깜빡이지 않음).
  • 이 부분은 클럭 없이 값이 바뀌는 즉시 반응하는 조합회로입니다.

8. 계산기

54    a    <= to_integer(unsigned(SW(17 downto 14)));
55    b    <= to_integer(unsigned(SW(13 downto 10)));
56    base <= 16 when SW(3) = '1' else 10;
57    res  <= a + b when SW(2 downto 1) = "00" else abs(a - b) when SW(2 downto 1) = "01" else a * b;
  • SW(17 downto 14)는 4비트 이진수입니다. unsigned(...)로 "부호 없는 숫자"로 보고 to_integer(...)로 정수로 바꿉니다. 이것이 A이고, 같은 식으로 SW13~10이 B입니다.
  • base : 16진수 모드(SW3 = 1)이면 16, 아니면 10. 결과를 몇 진수로 나눠 보일지 정합니다.
  • 연산 결과 res : when ... else로 연산(SW2~1)을 고릅니다. 00은 덧셈, 01은 뺄셈, 그 밖에는 곱셈입니다. 괄호 안의 처리는 아래와 같습니다.
    • 뺄셈 : abs(a - b)는 큰 수에서 작은 수를 뺀 절댓값입니다. 음수를 2의 보수로 다루지 않고 "크기 + 부호 표시"로 나눈 방식이고, 부호는 표시 단계에서 a < b일 때 -를 붙입니다. (3 - 7 → res = 4, 화면에 -와 04)
    • 곱셈 : a * b. 십진수 최대 9 × 9 = 81, 16진수 최대 15 × 15 = 225입니다.
    • 나눗셈(11) : 여기서는 계산하지 않고, 표시 단계에서 a / b(몫)와 a mod b(나머지)를 직접 씁니다.
  • 이 부분은 조합회로라 클럭이 없습니다. 스위치를 바꾸면 곧바로 결과가 바뀝니다.

9. 표시 : 어느 칸에 무엇을 띄울까

9-1. 먼저 전부 끄기

59    process (SW, cnt, a, b, base, res)
60    begin
61        d <= (others => BLANK);

모든 칸을 빈칸으로 두고 시작해서 필요한 칸만 아래에서 덮어씁니다. (others => BLANK)는 배열의 모든 칸을 한 값으로 채운다는 뜻이고, 같은 신호에 여러 번 대입하면 마지막 대입이 적용됩니다. 이 덕분에 "안 쓰는 칸은 끈다"를 일일이 적지 않아도 됩니다. 감지 목록 (SW, cnt, a, b, base, res)의 신호가 바뀔 때마다 다시 실행됩니다.

9-2. 카운터 표시

62        if SW(0) = '0' then
63            for i in 0 to 3 loop d(i) <= (cnt / 10 ** i) mod 10; end loop;
cnt = 1234i = 3 → d(3) (천)i = 2 → d(2) (백)i = 1 → d(1) (십)i = 0 → d(0) (일)
식 (cnt / 10 ** i) mod 101234 / 1000 mod 101234 / 100 mod 101234 / 10 mod 101234 / 1 mod 10
값1234

/는 몫, mod는 나머지, 10 ** i는 10의 i제곱(1, 10, 100, 1000)입니다. 7세그는 한 칸에 숫자 한 개만 띄울 수 있어서 십진수를 자릿수별로 쪼갭니다. for 반복문은 소프트웨어처럼 도는 것이 아니라 합성할 때 4줄로 펼쳐집니다. 카운터 모드에서는 HEX7~4를 쓰지 않아 빈칸입니다.

9-3. 계산기 표시

64        elsif a < base and b < base then
65            d(6) <= a;  d(4) <= b;
66            if SW(2 downto 1) /= "11" then
67                if SW(2 downto 1) = "01" and a < b then d(3) <= MINUS; end if;
68                d(1) <= res / base;  d(0) <= res mod base;
69            elsif b = 0 then
70                d(2) <= CH_E;  d(1) <= CH_R;  d(0) <= CH_R;
71            else
72                d(3) <= a / b;  d(1) <= CH_R;  d(0) <= a mod b;
73            end if;
74        end if;
  • A는 HEX6(d(6)), B는 HEX4(d(4))에 한 자리로 띄웁니다. 64번 줄의 a < base and b < base 때문에 십진수 모드에서 A나 B가 10 이상이면 이 부분을 건너뛰어, 61번 줄의 기본값대로 표시가 모두 꺼집니다. 16진수 모드는 base가 16이라 0~15가 항상 통과합니다.
  • 나눗셈이 아닌 연산(/= "11") : 뺄셈에서 A가 B보다 작으면 HEX3에 -. 결과 res를 base로 나눈 몫이 HEX1(d(1)), 나머지가 HEX0(d(0))이라 두 자리로 보입니다. 16진수 모드는 16으로, 십진수 모드는 10으로 나눕니다.
    예) 15 × 15 = 225 → 16진수 모드: 225 ÷ 16 = 14(E), 225 mod 16 = 1 → E1
  • 0으로 나눔(elsif b = 0) → E, r, r을 HEX2~0에 띄워 Err가 됩니다.
  • 나눗셈(else) → HEX3 = 몫(a / b), HEX2 = 빈칸, HEX1 = r, HEX0 = 나머지(a mod b). 예) 7 ÷ 3 → 2 r1. 이 줄은 B가 0이 아닐 때만 실행되므로 0으로 나누는 일이 없습니다.
  • 이 프로세스는 59~75번 줄입니다.

10. 출력 연결

77    HEX0 <= SEG7(d(0));  HEX1 <= SEG7(d(1));  HEX2 <= SEG7(d(2));  HEX3 <= SEG7(d(3));
78    HEX4 <= SEG7(d(4));  HEX5 <= SEG7(d(5));  HEX6 <= SEG7(d(6));  HEX7 <= SEG7(d(7));
79end behavior;

8개 칸 각각에서 문자 코드 d(N)을 SEG7 표의 칸 번호로 써서 7세그 패턴을 찾아 HEX 출력에 연결합니다. 마지막 end behavior;로 설계가 끝납니다.

12. 발표 예상 질문과 답

Q1. 버튼을 길게 눌러도 한 번만 올라가는 이유는?

누른 순간만 감지하기 때문입니다. 한 클럭 전 버튼 값(k2)이 1이고 지금 값(k1)이 0인 클럭에서만 ed가 1이 되어 값이 바뀝니다. 버튼을 계속 눌러도 이 조건은 처음 한 번만 참입니다.

Q2. 왜 k1, k2 두 개를 쓰나요?

하나는 현재 값, 하나는 한 클럭 전 값을 저장해서 "1에서 0으로 바뀌었는지"를 비교하려고 쓰고, 버튼이 클럭과 상관없이 바뀌는 신호이므로 레지스터에 한 번 담아 안정화하는 역할도 합니다.

Q3. 왜 integer range 0 to 9999처럼 정수를 썼나요?

코드가 읽기 쉽고, 범위만 적어 주면 합성할 때 필요한 비트 수(여기서는 14비트)로 알아서 만들어지기 때문입니다. 자릿수 분리(/, mod)도 정수로 하면 간단합니다.

Q4. 음수는 어떻게 처리했나요?

abs(a - b)로 큰 수에서 작은 수를 뺀 값을 res에 넣고, 표시 단계에서 a < b이면 HEX3에 -를 띄웁니다. 2의 보수 대신 "크기 + 부호"로 나눈 방식입니다.

Q5. 표시 프로세스 맨 위에서 전부 BLANK로 두는 이유는?

어떤 경우에도 모든 칸에 값이 정해지게 하려는 것입니다. 값이 정해지지 않는 경우가 생기면 회로가 이전 값을 기억하는 래치를 만들 수 있습니다. "먼저 전부 끄고 필요한 칸만 덮어쓰기" 용도이기도 합니다.

Q6. 0으로 나누면 어떻게 되나요?

표시 단계에서 b = 0을 먼저 검사해 Err를 띄웁니다. 나눗셈(a / b)은 그 검사를 통과한 else 안에서만 하므로 B가 0일 때는 계산하지 않습니다.

Q7. 나머지는 어떻게 구하나요?

a mod b로 구합니다. 몫은 a / b입니다. 7 ÷ 3이면 몫 2, 나머지 1입니다.

Q8. 16진수 표시는 어떻게 했나요?

SW3이 1이면 base가 16이 되어 res / base(윗자리)와 res mod base(아랫자리)가 16으로 나눈 몫과 나머지가 됩니다. 십진수 모드에서는 같은 식이 10으로 나눕니다. SEG7 표에 10~15의 패턴(A, b, C, d, E, F)이 들어 있어서 이 값들이 문자로 보입니다.

Q9. 777 잭팟은 어떻게 구현했나요?

cnt = 777인지 비교합니다. 참이면 초록 LED(LEDG) 8개를 모두 켠 채 유지합니다(깜빡이지 않음). 7세그먼트에는 따로 표시하지 않고 값 777이 그대로 보입니다. 777에서 벗어나면 꺼집니다. 빨간 LED는 잭팟일 때도 계속 값(777)의 이진수를 보여 줍니다.

Q10. 두 버튼을 동시에 누르면요?

다음 값 n의 when ... else 순서(KEY0 → KEY3 → KEY2 → KEY1)대로 하나만 적용됩니다. 이것은 두 눌림이 같은 클럭(20ns)에 겹칠 때만이고, 손으로 누르면 몇 ms 어긋나서 두 에지가 따로 잡혀 둘 다 적용됩니다. 예) KEY3과 KEY2를 거의 동시에 누르면 +1 후 +2로 +3, KEY3을 먼저 누르고 KEY0을 누르면 0, KEY0을 먼저 누르고 KEY3을 누르면 1입니다(보드에서 확인). 동시 입력에 대한 규칙은 과제에 따로 없습니다.

Q11. 9999에서 더 올리면요? 0에서 내리면요?

n이 9999를 넘으면 9999로, 0보다 작아지면 0으로 고정합니다. (예: 9995에서 +10 → 9999, 2에서 -5 → 0) n의 범위를 -5~10009로 잡은 것은 이렇게 한도를 넘는 값을 잠깐 담기 위해서입니다.

Q12. 카운터는 클럭을 쓰는데 계산기는 왜 안 쓰나요?

카운터는 값을 기억하고 버튼을 누른 순간을 감지해야 해서 클럭에 맞춰 동작하는 순차회로입니다. 계산기는 스위치 값으로만 결과가 정해지고 기억할 필요가 없어서 입력이 바뀌면 바로 반응하는 조합회로입니다.

Q13. 신호 대입(<=)은 언제 값이 바뀌나요?

프로세스가 끝난 뒤에 바뀝니다. 그래서 클럭 프로세스에서 k1 <= KEY; k2 <= k1;을 한 줄에 써도 k2에는 갱신 전의 k1(한 클럭 전 값)이 들어갑니다. 표시 프로세스에서는 같은 신호에 여러 번 대입하면 마지막 대입이 적용되는 점을 이용합니다.

Q14. 7세그먼트는 왜 0일 때 켜지나요?

DE2 보드의 7세그먼트는 active-low 방식이라 해당 획에 0을 주면 켜지고 1을 주면 꺼지기 때문입니다. 숫자 0은 g만 끄면 되므로 "1000000"입니다.

Q15. 십진수 모드에서 A나 B에 10 이상을 넣으면 어떻게 되나요?

계산기 표시가 모두 꺼집니다. 한 자리 십진수는 0~9라서, 64번 줄 elsif a < base and b < base가 거짓이면 아무 것도 쓰지 않고 61번 줄의 빈칸 기본값이 남습니다. 줄 수는 늘지 않았습니다(else를 바꿈). 이 검사가 없으면 16진수 글자가 보이고, 14 × 14 같은 곱은 res / 10이 숫자표 범위(0~18)를 넘습니다. 0~F를 쓰려면 SW3을 1로 올려 16진수 모드로 바꿉니다.

Q16. 10 ** i와 for는 무슨 뜻인가요?

**는 거듭제곱이라 10 ** i는 10의 i제곱(1, 10, 100, 1000)입니다. for i in 0 to 3 loop는 i가 0~3일 때의 줄을 하드웨어로 4개 펼쳐 줍니다. 즉 d(0) <= cnt mod 10, d(1) <= (cnt / 10) mod 10 같은 네 줄과 같습니다.

13. 시연 순서 (제안)

  1. 카운터 (SW0 = 0) : 0000 확인 → KEY3을 길게 눌러도 +1만 되는지 → KEY2 → KEY1 → SW1을 올려 +5 / +10 / -5 → KEY0 리셋.
  2. LED : 값이 바뀔 때 빨간 LED가 이진수로 바뀌는지 확인.
  3. 잭팟 : 777을 만들면(예: SW1을 올려 KEY2로 +10을 77번, SW1을 내려 KEY3으로 +1을 7번) 초록 LED 전부 켜짐.
  4. 계산기 (SW0 = 1) : A = 7, B = 3으로 덧셈 → 뺄셈 → 곱셈 → 나눗셈(2 r1). A와 B를 바꿔 - 04, B = 0으로 Err.
  5. 16진수 (SW3 = 1) : A = 15, B = 15로 곱셈 → E1. SW3을 내려 십진수로 돌아갑니다(십진수 모드에서는 A, B를 0~9로 맞춰 시연).

1library ieee;
2use ieee.std_logic_1164.all;
3use ieee.numeric_std.all;
4
5entity DE2_Project1 is
6    port (CLOCK_50 : in  std_logic;
7          KEY      : in  std_logic_vector(3 downto 0);
8          SW       : in  std_logic_vector(17 downto 0);
9          LEDR     : out std_logic_vector(17 downto 0);
10          LEDG     : out std_logic_vector(7 downto 0);
11          HEX0, HEX1, HEX2, HEX3, HEX4, HEX5, HEX6, HEX7 : out std_logic_vector(6 downto 0));
12end DE2_Project1;
13
14architecture behavior of DE2_Project1 is
15    constant BLANK : integer := 16;
16    constant MINUS : integer := 17;
17    constant CH_R  : integer := 18;
18    constant CH_E  : integer := 14;
19
20    type seg_table is array (0 to 18) of std_logic_vector(6 downto 0);
21    constant SEG7 : seg_table := (
22        "1000000", "1111001", "0100100", "0110000", "0011001",
23        "0010010", "0000010", "1111000", "0000000", "0010000",
24        "0001000", "0000011", "1000110", "0100001", "0000110", "0001110",
25        "1111111", "0111111", "0101111");
26
27    type digits is array (7 downto 0) of integer range 0 to 18;
28    signal d      : digits;
29    signal k1, k2 : std_logic_vector(3 downto 0) := "1111";
30    signal ed     : std_logic_vector(3 downto 0);
31    signal cnt    : integer range 0 to 9999 := 0;
32    signal n      : integer range -5 to 10009;
33    signal s      : integer range 1 to 5;
34    signal a, b   : integer range 0 to 15;
35    signal base   : integer range 10 to 16;
36    signal res    : integer range 0 to 255;
37begin
38    ed <= k2 and not k1;
39    s  <= 1 when SW(1) = '0' else 5;
40    n  <= cnt when SW(0) = '1' else 0 when ed(0) = '1' else cnt + s when ed(3) = '1' else
41          cnt + 2 * s when ed(2) = '1' else cnt - s when ed(1) = '1' else cnt;
42
43    process (CLOCK_50)
44    begin
45        if rising_edge(CLOCK_50) then
46            k1 <= KEY;  k2 <= k1;
47            if n < 0 then cnt <= 0; elsif n > 9999 then cnt <= 9999; else cnt <= n; end if;
48        end if;
49    end process;
50
51    LEDR <= std_logic_vector(to_unsigned(cnt, 18)) when SW(0) = '0' else (others => '0');
52    LEDG <= (others => '1') when SW(0) = '0' and cnt = 777 else (others => '0');
53
54    a    <= to_integer(unsigned(SW(17 downto 14)));
55    b    <= to_integer(unsigned(SW(13 downto 10)));
56    base <= 16 when SW(3) = '1' else 10;
57    res  <= a + b when SW(2 downto 1) = "00" else abs(a - b) when SW(2 downto 1) = "01" else a * b;
58
59    process (SW, cnt, a, b, base, res)
60    begin
61        d <= (others => BLANK);
62        if SW(0) = '0' then
63            for i in 0 to 3 loop d(i) <= (cnt / 10 ** i) mod 10; end loop;
64        elsif a < base and b < base then
65            d(6) <= a;  d(4) <= b;
66            if SW(2 downto 1) /= "11" then
67                if SW(2 downto 1) = "01" and a < b then d(3) <= MINUS; end if;
68                d(1) <= res / base;  d(0) <= res mod base;
69            elsif b = 0 then
70                d(2) <= CH_E;  d(1) <= CH_R;  d(0) <= CH_R;
71            else
72                d(3) <= a / b;  d(1) <= CH_R;  d(0) <= a mod b;
73            end if;
74        end if;
75    end process;
76
77    HEX0 <= SEG7(d(0));  HEX1 <= SEG7(d(1));  HEX2 <= SEG7(d(2));  HEX3 <= SEG7(d(3));
78    HEX4 <= SEG7(d(4));  HEX5 <= SEG7(d(5));  HEX6 <= SEG7(d(6));  HEX7 <= SEG7(d(7));
79end behavior;
