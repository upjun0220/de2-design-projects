1전체 흐름

펜 끝 자석의 자기장을 센서 4개가 읽고, 위치를 복원해 서명 궤적을 만들고, 등록된 서명과 비교해 누구인지 고른다.

자석 펜→ MLX90393 ×4→ I²C → I²C 리더 (Verilog)→ 기준값 빼기 · 장착 보정→ 위치 MLP (x, y, z, ux, uy)→ 필터→ 서명 버퍼 (SW17)→ 전처리 128×8→ DTW (SW / HW)→ 판정→ LCD · VGA · LED · 7세그
색: FPGA 하드웨어 Nios II C PC(Python)
쌍극자 시뮬레이션→MLP 학습·정수화→mlp_weights.h· 9점 측정 → gate1.py (장착·세기)·수집 로그 → evaluate.py (문턱)
  • DE2가 하는 일: 센서 읽기부터 판정·표시까지 전부(독립 동작). 50 Hz로 한 프레임씩 처리한다.
  • PC가 하는 일: 학습, 정수화, 측정 분석. 결과는 C 헤더(mlp_weights.h, config.h)로 보드에 들어간다.
  • 코드 위치: hdl/ Verilog, nios/ C, pc/ Python. 설정값은 모두 nios/config.h 한 곳에 있다.

2자기 쌍극자 모델

작은 자석은 멀리서 보면 "자기 쌍극자"로 근사된다. 위치를 구하는 모든 계산의 바탕이다.

B(r) = (μ0 / 4π) · [ 3 (m·r̂) r̂ − m ] / |r|³
  • r: 자석 중심에서 센서까지의 벡터. m: 자기 모멘트(세기 × 극 방향 단위벡터). 세기 단위 A·m².
  • 거리의 세제곱에 반비례한다. 2배 멀어지면 1/8. 그래서 센서값의 범위가 수천 배로 넓다 → MLP 입력에 세제곱근을 쓴다(5장).
  • 근사가 맞는 거리: 자석 크기의 약 3배 이상. 자석이 φ10×10 mm라 약 3 cm 이상이면 잘 맞는다. 센서는 서명 영역에서 4~10 cm 떨어져 있다.
  • 미지수: 위치 3개(x, y, z) + 극 방향 2개(펜 기울기) = 5개. 자석 세기도 모르면 6개. 측정값은 센서 4개 × 3축 = 12개라 풀 수 있다.
  • 펜 축 둘레 회전(롤)은 관측되지 않는다. 축 방향 자석은 롤과 무관하다 → 11/19에 자석을 펜 끝에 축 방향으로 다시 붙인 이유다(옆에 붙이면 쥐는 각도에 따라 극 방향이 바뀐다).
한계 시뮬레이션은 참값 생성과 추정에 같은 쌍극자 모델을 쓴다("inverse crime"). 실제 자석의 비이상성, 주변 철, 센서 위치 오차는 반영되지 않아 실측은 시뮬레이션보다 나쁘게 나온다.

3센서와 I²C

MLX90393은 3축 홀 센서다. FPGA 안의 Verilog I²C 마스터가 4개를 차례로 읽는다.

항목값근거

주소0x18~0x1B (A0/A1 핀으로 4개)11/18 보드 스캔 실측
버스1개, SCL 200 kHz, 한 프레임 전송 약 2.6 mshdl/i2c_master.v, BRINGUP

I²C 핵심

  • 선 2개: SCL(클럭), SDA(데이터). 둘 다 오픈 드레인 — 장치는 선을 0으로 당기기만 하고, 1은 풀업 저항이 만든다.
  • SDA는 SCL이 0일 때만 바뀐다. SCL이 1일 때 SDA가 바뀌는 것은 START(1→0)와 STOP(0→1)뿐이다.
  • 바이트마다 받는 쪽이 SDA를 0으로 당겨 ACK한다. 주소를 보냈는데 ACK가 없으면 그 주소에 장치가 없다 → 부팅 때 I²C 스캔이 이것으로 센서를 찾는다.
  • 구현: SCL 한 주기를 4단계로 나눈다(CLK_HZ/(4·SCL_HZ) 클럭씩). SCL을 놓은 뒤 실제로 1이 됐는지 확인하고 넘어간다(clock stretching 대응).

4장착 보정과 기준값

센서가 내놓는 값을 "보드 좌표계의 자석 자기장"으로 바꾸는 단계. 11/18까지 위치가 크게 틀린 원인이 여기에 있었다.

기준값 빼기 (KEY0)

  • 펜이 없을 때의 값(지구 자기장, 센서 오프셋)을 32프레임 평균해 저장하고, 매 프레임 뺀다.
  • 펜을 50 cm 이상 치우고 눌러야 한다. 펜이 가까이 있으면 그 자기장까지 빠져서 위치가 체계적으로 틀어진다(11/18 실제로 겪음).
  • 센서 4개가 거의 같은 벡터를 보면(UNIFORM_PCT 20%) 펜이 아니라 보드 회전·먼 물체로 보고 무시한다.

장착 보정 (mount_correct)

  • MOUNT_ROT: 센서별로 패드에 붙은 방향(90° 단위 회전 0~3).
  • Z_SIGN: Z축 방향. FIELD_SIGN: 자석 극 전체 부호.
  • MIRROR_XY: X·Y 교환(거울상). 회전과 Z 반전만으로는 거울상을 만들 수 없다(회전은 방향을 보존하는 변환이고 거울상은 뒤집는 변환이라). 그래서 따로 둔다.
  • 값은 pc/gate1.py --find-mount가 9점 측정 로그에서 찾는다: 회전 4⁴ × Z 2 × 거울 2 = 1024가지를 전부 피팅해 잔차가 가장 작은 조합.
평면 배열의 모호성 센서가 한 평면에 있으면, Z 방향만 뒤집은 장착이 "판 아래 거울 위치의 자석"으로 잔차가 정확히 같게 맞는다. 그래서 탐색은 자석이 판 아래(z < 0)로 풀리는 조합을 버린다(11/19 실측에서 발견).
교훈 3점만으로 순위를 매기면 센서 하나의 회전 차이가 5%밖에 안 나서 틀린 답을 골랐다. 이제 상위 10개를 9점 전체로 다시 채점한다.

5위치 추정: LM과 MLP

같은 문제(12개 측정 → 위치·방향)를 PC에서는 반복 최적화로, 보드에서는 작은 신경망으로 푼다.

LM 피팅 (PC, 기준선)

  • Levenberg–Marquardt: 쌍극자 모델의 예측값과 측정값의 차이(잔차) 제곱합을 최소로 만드는 x, y, z, m을 반복해서 찾는다.
  • 미지수 6개: 위치 3 + 자석 벡터 3(방향과 세기를 함께). 세기를 고정하면 실제 세기가 다를 때 위치가 크게 틀린다 — 합성 시험에서 실제 0.5, 가정 0.9이면 xy 53~79 mm 시뮬레이션.
  • 국소 최적화라 시작점이 중요하다 → 여러 시작점(위치 × 방향 6개)에서 풀고 잔차가 가장 작은 해를 쓴다.
  • 쓰는 곳: gate1.py(장착값·자석 세기·오차 측정), evaluate.py --lm(로그를 다시 계산).

위치 MLP (보드)

  • 구조: 입력 12 → 은닉 64 → 은닉 64 → 출력 5(x, y, z, ux, uy). ReLU. 프레임당 곱셈 5,184번 — Nios II/f 하드웨어 곱셈기로 50 Hz 안에 끝난다.
  • 입력: 센서값의 세제곱근(부호 유지). 1/r³로 넓어진 범위를 압축해 가까운 곳과 먼 곳을 고르게 다룬다. Z는 감도 비(0.403/0.250)로 맞춘다.
  • 학습 데이터: 쌍극자 모델로 만든 합성 데이터(서명 영역 ±5 cm, 높이, 펜 기울기 0~60°, 센서 위치 1 mm·이득 2% 오차 섞음). 실측 참값이 필요 없다.
  • 11/19 재학습: 축 방향 자석, 세기 0.57 A·m², 높이 2 mm부터 → 서명 영역 xy 2.6 mm, z 2.1 mm 시뮬레이션.
  • 왜 LM을 보드에서 안 쓰나: 반복 계산과 실수 연산이 필요해 Nios II에서 50 Hz를 맞추기 어렵다. MLP는 정해진 횟수의 정수 곱셈뿐이다.

6고정소수점과 비트 일치 검증

보드 계산은 전부 정수다. Python 기준 구현과 C가 비트 하나까지 같은지 자동으로 확인한다.

  • Qn 표기: 실수에 2ⁿ을 곱해 정수로 저장. Q12면 1.0 = 4096. 곱하면 소수 자리가 더해지므로 >> n으로 되돌린다.
  • 쓰는 형식: MLP 가중치 Q10, 은닉값 Q6(4095에서 자름), 출력 Q12. 필터 상태 Q4, 계수 Q12. 위치 단위는 0.1 mm.
  • 32비트 넘침을 학습 스크립트가 검사한다(합 최대값 출력). 필터는 입력을 ±400 mm로 잘라 곱이 32비트 안에 들게 한다.
  • 음수 나눗셈 주의: C의 /는 0 쪽으로 버리고 Python의 //는 내림이다. Python 쪽은 tdiv로 C와 맞춘다.

검증 체계 (sh design2/run_checks.sh)

  1. Python 기준 모델 자체 검사(위치, 필터, 장착 탐색, 평가, 로그 파서 등).
  2. gen_golden.py가 입력과 Python 정답을 파일로 쓰고, PC에서 컴파일한 C(test_host.c)가 같은 입력으로 계산해 비교 → C core OK.
  3. ModelSim으로 Verilog(I²C 리더, DTW 가속기 테스트 벡터 100개, VGA 화면) 시뮬레이션.
주의 이 검사들은 "C가 Python과 같다", "Verilog가 기준 모델과 같다"를 보장할 뿐이다. 보드에서 실제로 맞는지는 별개로 확인해야 한다.

7위치 필터 (중앙값 + 1€)

추정 위치는 프레임마다 몇 mm씩 흔들린다. 흔들림을 누르면 늦게 따라오는 맞바꿈이 있다.

  1. 3점 중앙값: 최근 3개 값의 가운데. 한 프레임만 튀는 값이 사라진다. 대가는 1프레임(20 ms) 지연 — 100 mm/s에서 2 mm.
  2. 1€ 필터(Casiez·Roussel·Vogel, CHI 2012): 1차 저역 통과 필터 x ← x + α(입력 − x)의 차단 주파수를 속도에 따라 바꾼다.
fc = PF_MINCUT + PF_BETA × |속도| (속도도 PF_DCUT로 거른다) α = w / (1 + w), w = 2π · fc · Te, Te = 0.02 s (50 Hz)
  • 멈춰 있으면 fc가 낮아(1 Hz) 세게 다듬고, 빠르게 그으면 fc가 올라가 덜 늦는다.
  • 필터를 거친 위치가 저장·표시·로그에 쓰인다. 펜이 사라지면 필터를 처음부터 다시 시작한다.

정직하게 움직이는 구간의 정확도는 필터가 없을 때가 가장 좋다. 필터는 화면 안정과 펜 뗌 판정을 위한 것이다. 화면용 데드밴드(ANCHOR_R 1.5 mm)는 화면에만 적용하고 저장 서명은 바꾸지 않는다.

8서명 시작·끝 판정

추정 높이만으로는 "펜이 종이에 닿았는가"를 가를 수 없어서 스위치(SW17)를 쓴다.

  • SW17 켬 = 서명 시작, 끔 = 끝. 최대 10초(500프레임).
  • 획 사이 펜 뗌: 닿은 높이 z_ref보다 LIFT_UP(8 mm) 넘게 올라가면 뗌, LIFT_DOWN(5 mm) 안으로 오면 다시 닿음. 문턱이 두 개인 히스테리시스라 경계에서 깜빡이지 않는다.
  • z_ref 추적: 펜이 닿아 있는 동안 높이를 따라간다(낮아지면 바로, 높아지면 천천히 약 0.6초). 교정 전이라 자리마다 닿은 높이가 몇 mm씩 달라서다. 뗌 판정을 먼저 하고 추적은 나중에 한다.
  • 꼬리 자르기(sig_trim_tail): 마지막 획 → 펜 들기 → 스위치로 손 이동 → 끔. 펜을 든 뒤의 움직임은 서명이 아니다.
    1. 높이를 앞뒤 2프레임 평균으로 다듬는다(다 저장된 뒤라 지연이 없다).
    2. 끝에서 15 mm(TRIM_LIFT) 넘게 떠 있고 다시 안 내려왔으면(최근 3초 안), 펜을 들고 끝낸 것이다.
    3. 높이가 계속 낮아지는 쪽으로 거슬러 가서 가장 낮은 점(종이를 떠난 곳) 다음을 자른다.
    못 찾으면 자르지 않는다 — 틀려도 획이 잘리지 않고 꼬리가 남는 쪽으로 틀린다.
서명하는 법 획 사이엔 살짝 떼고, 끝에는 펜을 2~3 cm 확 들어 올린 뒤 다시 내리지 말고 SW17을 끈다.

9전처리 (128×8)

길이·위치·크기가 제각각인 서명을 같은 형식으로 맞춘다. 정수만 쓰고 Python과 비트 일치.

  1. 리샘플: 시간축을 128점으로 선형 보간(서명 길이와 무관하게).
  2. 정규화: 펜이 닿은 점들의 무게중심을 원점으로, 가로 폭을 100으로 맞춘다 → 어디에 얼마나 크게 쓰든 같아진다.
  3. 채널 8개 (int8): x, y, z(가장 낮은 점 기준, 0.4 mm 단위), vx, vy(중앙 차분), ux, uy(극 방향 수평 성분), pen(64 = 닿음, 0 = 뗌).
  4. CHANNEL_MASK로 쓰지 않을 채널을 0으로 만든다.
지금 문제 8개 채널을 모두 쓰고 있다. 높이·기울기는 잡음이 커서 본인 서명끼리의 거리도 키운다 → 문턱 tau가 커져 아무 서명이나 통과한다(11/19). 수집 데이터로 채널 조합을 정할 예정.

10DTW (Dynamic Time Warping)

같은 사람도 서명 속도가 매번 다르다. DTW는 시간축을 늘이고 줄여 가장 잘 맞는 정렬을 찾은 뒤 거리를 잰다.

d(i, j) = Σ_c |A[i][c] − B[j][c]| (채널별 절대차 합, L1) D[i][j] = d(i, j) + min( D[i−1][j], D[i][j−1], D[i−1][j−1] ) 거리 = D[127][127], 대역 |i − j| ≤ 16 (Sakoe–Chiba)
  • 동적계획법: 128×128 표를 채운다. 각 칸은 "여기까지 오는 가장 싼 경로". 대역 밖은 계산하지 않는다(대역 안 3,952칸).
  • 대역을 두는 이유: 계산량 감소, 그리고 지나치게 늘이는 비현실적인 정렬 방지.
  • 곱셈이 없다(뺄셈·절댓값·최솟값만) → 하드웨어로 만들기 좋다. 한 칸 값은 최대 8×255 = 2040(11비트), 누적은 24비트에서 포화.
  • 왜 DTW: 사람 수와 서명 수가 적을 때는 학습형 모델보다 DTW 같은 템플릿 비교가 안정적이다. 등록 = 템플릿 5개 저장이라 보드에서 바로 끝난다.
  • 사람별 거리 = 그 사람 템플릿 5개 중 가장 가까운 것(문헌은 평균도 씀 → evaluate.py --agg mean으로 비교 예정).

11DTW 하드웨어 가속기

DE2의 역할: DTW를 FPGA 병렬 처리 소자(PE) 배열로 만들어 소프트웨어와 지연·자원을 비교한다.

  • 안티대각선 병렬성: D[i][j]는 왼쪽·위·왼쪽위 칸만 필요하다. 그래서 같은 안티대각선(i+j가 같은 칸들)은 서로 의존하지 않아 동시에 계산할 수 있다.
  • 시스톨릭 배열: 대역 폭만큼 PE 33개(2×16+1)를 한 줄로 놓고, 각 PE는 오프셋 i−j 하나를 맡는다. PE는 이웃과만 값을 주고받는다 → 배선이 단순하고 클럭을 높이기 쉽다.
  • 곱셈기 0개. 템플릿 25개(5명 × 5)가 온칩 RAM에 들어간다.
  • 비교 1회 276클럭, 템플릿 25개 6,900클럭 ModelSim → 50 MHz면 약 138 µs. 보드 측정(7세그)은 아직.
  • 검증: 테스트 벡터 100개(무작위, 동일, 최대 차이, 대역 경계)에서 하드웨어 = Python 100/100 ModelSim.
  • Nios II에서는 Avalon-MM 레지스터(CTRL, STATUS, N_TEMPL, CYCLES, RESULT[k])로 쓴다. SW[5]로 SW/HW 전환.
정직하게 DTW 25회는 노트북에서도 1 ms 안에 끝난다. 이 가속기의 목적은 "DE2 없이는 불가능"이 아니라 HW/SW 분할을 설계하고 지연·자원을 정량 비교하는 것이다. 시스톨릭 DTW 구조 자체는 표준적인 방법이다.

12판정 규칙과 평가 지표

tau_k = μ_k + a · σ_k (등록 서명 5개끼리 거리 10쌍의 평균·표준편차, a = TAU_A = 2) 판정: d_k1 < tau_k1 그리고 d_k2 − d_k1 ≥ MARGIN_M → 등록자 k1, 아니면 "미등록"
  • k1, k2: 거리가 가장 가까운 두 사람. 둘째와 차이가 작으면 헷갈리는 것으로 보고 미등록 처리한다.
  • 한 사람만 등록돼 있으면 둘째 비교가 없어 tau 하나로만 판정한다.

13DE2 시스템 (Nios II, Qsys)

  • Nios II/f: FPGA 안에 만든 32비트 소프트 CPU(명령·데이터 캐시, 하드웨어 곱셈기, 나눗셈은 소프트웨어). 무료판(OpenCore Plus)은 USB-Blaster가 연결되고 quartus_pgm 창이 열려 있는 동안만 돈다 → 시연도 PC를 연결한 채로 한다.
  • Qsys 구성: CPU, SDRAM(프로그램·데이터 8 MB), JTAG UART, 타이머, PIO(스위치·키·LED·7세그), 문자 LCD, 사용자 정의 부품 3개(mlx_reader, dtw_accel, vga_ui).
  • SDRAM 클럭 위상: SDRAM은 CPU 클럭보다 조금 앞당긴 클럭을 받아야 데이터를 제때 읽는다. Altera 예제 값 −3 ns는 실패하고 −1 ns에서 성공 실측 11/16.
  • 화면: VGA 80×30 글자 + 192×192 서명 칸 비트맵(Verilog). 같은 화면을 JTAG UART로 노트북에 보내 screen.py가 그린다(모니터 없이 시연). '@'로 시작하는 줄이 화면 명령이다.
  • 빌드: FPGA를 바꾸면 quartus/build.sh(오래 걸림), C만 바꾸면 nios/build.sh → nios2-download -g(1~2분).

15예상 질문

센서 4개로 어떻게 3차원 위치를 구하나?

센서 하나가 3축이라 측정값은 12개다. 미지수는 위치 3 + 극 방향 2 (+ 자석 세기 1) = 5~6개라 식이 미지수보다 많다. 쌍극자 모델로 측정값을 가장 잘 설명하는 위치를 찾는다(PC는 LM, 보드는 그걸 흉내 내도록 학습한 MLP).

왜 MLP를 쓰나? LM으로 충분하지 않나?

LM은 반복 계산과 실수 연산이 필요하고 시작점에 따라 결과가 갈린다. MLP는 정해진 횟수의 정수 곱셈(5,184번)이라 Nios II에서 50 Hz를 맞추고, 실행 시간이 일정하다. 학습은 쌍극자 모델로 만든 합성 데이터로 해서 실측 참값이 필요 없다.

시뮬레이션 2.6 mm인데 실측은 왜 더 나쁜가?

시뮬레이션은 참값과 추정에 같은 쌍극자 모델을 쓰고, 센서 위치·자석 세기·높이를 정확히 안다고 가정한다. 실물은 센서 위치 오차, 자석 비이상성, 격자를 그린 위치 오차가 있다. 11/19 실측 11.7 mm 중 대부분은 일정한 밀림(격자 중심 어긋남 추정)이고, 이를 빼면 3.3 mm다.

DTW를 FPGA로 만든 이유는? 노트북이면 금방 하지 않나?

맞다, 노트북에서도 1 ms 안에 끝난다. 목적은 속도 자체가 아니라 HW/SW 분할 설계와 정량 비교(지연, LE, 곱셈기, 메모리)다. DTW는 곱셈 없이 안티대각선 병렬성이 있어 시스톨릭 배열로 만들기 좋다.

위조 서명도 걸러내나?

아니다. 이 장치는 등록된 사람 중 누구인지 고르는 "식별"이다. 따라 쓰기 위조 실험은 한계를 수치로 보고하는 용도이고, 보안·인증 기능이라고 주장하지 않는다.

왜 높이로 펜 뗌을 판정하지 않고 스위치를 쓰나?

교정 전 추정 높이는 자리마다 몇 mm씩 다르고 흔들려서, 종이에 닿았는지를 높이만으로 가를 수 없었다(실측). 스위치로 서명 시작과 끝을 확실히 정하고, 그 안에서 획 사이 뗌만 상대 높이로 판정한다.

Z_SIGN은 어떻게 정했나?

센서가 한 평면에 있으면 Z 방향을 뒤집은 장착이 판 아래 거울 위치의 자석으로 똑같이 맞는다. 물리적으로 자석은 판 위에 있으므로 z > 0으로 풀리는 쪽을 골랐다.

AI를 어디에 썼고 어떻게 검증했나?

코드 작성, 시뮬레이션 설계, 원인 분석에 썼다. 검증은 Python 기준 구현과 C·Verilog의 비트 일치 시험, 합성 데이터 자체 검사, 보드 실측으로 했다. AI가 틀린 사례(버스를 나누면 빨라진다는 제안, 3점으로 장착을 고른 것, z_ref 정수 시프트 버그 등)는 일지에 기록돼 있다.
