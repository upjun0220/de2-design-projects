## 0. Claude Code에게: 작업 원칙

- 응답과 주석은 **한국어**, 코드 식별자는 영어. (단 HDL·C 소스 주석은 영어 ASCII — `../CLAUDE.md` 참고. 저장소 공통 규칙도 `../CLAUDE.md`.)
- **정직하고 기술적으로 엄밀하게.** 확인한 것과 추정한 것을 구분한다. 근거 없는 수치를 확정처럼 쓰지 않고, 시뮬레이션 숫자를 실측처럼 말하지 않는다. 틀린 곳이 보이면 조용히 고치지 말고 알린다.
- **요청한 범위만 수정한다.** 기존 문서·코드의 스타일을 유지하고, 요청하지 않은 리팩터링·기능 추가를 하지 않는다.
- 하드웨어 전압은 **3.3 V 로직만**(Cyclone II는 5 V 비내성). 5 V를 연결하는 코드·배선을 제안하지 않는다.
- 서명 데이터는 개인정보다. 파일명은 이름 대신 번호를 쓰고, 수집 전 동의가 전제다.
- **이해 우선(평가 기준 때문):** 이 과제는 두 사람이 만든 것을 얼마나 이해하는지도 채점한다. 새 모듈을 만들기 전에 원리를 짧게 설명하고, 코드 머리에 입출력·동작 원리·검증 방법을 주석으로 남긴다. 두 사람이 설명하기 어려운 블랙박스(복잡한 문법, 출처 불명의 트릭)는 피하고 간결하게 쓴다.
- **최소 동작 데모 우선(Quality):** 반쯤 되는 기능 여러 개보다 끝까지 안정적으로 도는 작은 데모가 낫다. 선택 기능은 필수 경로가 돌아간 뒤에 얹는다(5장).
- 이 폴더(`design2/`)는 Design Project #2 전용이다. Design Project #1(`../design1/`, VHDL, AI 사용 제한 과제) 코드는 건드리지 않는다.
- 세션을 마칠 때 15장의 저널 초안을 남긴다.

- **주제:** 펜 끝 영구자석의 자기장을 3축 자기 센서 배열로 읽어 펜의 3차원 위치·기울기를 복원하고, 서명 한 번의 시계열로 **누가 썼는지 식별**한다. 등록자면 이름, 아니면 "미등록".

- **AI 요소:** (1) 위치 복원 MLP, (2) 서명 임베딩 1D CNN(Nios II 소프트웨어 int8). DTW는 기준선이면서 **FPGA 병렬 PE 배열로 만들어 소프트웨어와 지연·LE·곱셈기를 비교**하는 것이 DE2의 역할이다(8장).

## 5. 범위 계층 (제안, 팀 합의 필요)

Quality 기준상 "끝까지 도는 것"이 우선이므로 아래 순서로 쌓고, 윗단이 안정적으로 돌기 전에 아랫단을 시작하지 않는다.

- **Tier 0 — 최소 완성품(MVP):** 센서 4개 → I²C 읽기 → 위치 복원 → 서명 버퍼 → **소프트웨어 DTW 식별** → LCD에 영문 이름/미등록, LED.
- **Tier 1 — DE2의 역할(결정됨):** DTW 병렬 PE 배열(HW) 및 SW/HW 비교표, 7세그 지연. 위치 MLP.
- **Tier 2 — 선택:** 임베딩 CNN(int8, Nios II SW), VGA 2D·3D 표시와 한글 이름, 현장 등록 모드, 허공 서명.

11/20 리허설에서 3회 연속 성공해야 하는 것은 Tier 0 + Tier 1이다(12장).

## 6. 시스템 구성

```
자석 펜 ─(자기장)→ MLX90393 ×4 ─I²C→ [I²C 마스터(Verilog)] → 샘플 FIFO
  → 기준값 차감(KEY0로 재측정) → 위치 MLP(기준선: LM) → (x, y, z, θ, φ) @ ~50 Hz
  → 서명 버퍼(시작/끝 판정, SDRAM) → 전처리(정규화·128점 리샘플·8채널 int8)
  → DTW(SW / HW PE 배열)  [+ 선택: 임베딩 1D CNN(32차원)]  → 판정(등록자 ID / 미등록)
  → LCD(영문), VGA(한글·2D 서명·3D 궤적), LED, 7세그(지연)
PC(오프라인): 시뮬레이션·학습·int8 양자화·.hex 출력, JTAG UART로 로그 수신
```

### 6.1 위치 복원

- 모델: 자기 쌍극자 `B = (μ0/4π)[3(m·r̂)r̂ − m]/r³`, m = M0·(sinθcosφ, sinθsinφ, cosθ). 센서 4개 × 3축 = 12개 측정 → 5자유도(x, y, z, θ, φ). 펜 축 자체 회전은 관측 불가(필요 없음).
- 기준값 차감으로 지자기·고정 오프셋 제거(연철 왜곡은 제거 못 함).
- 기준선은 Levenberg–Marquardt, 다중 시작점은 첫 프레임에서만, 이후는 직전 해로 warm-start. 목표 MLP는 입력 12 → 출력 5(약 5k MAC 이하, 추정).
- 쌍극자 근사는 자석 크기(10 mm)의 약 3배(30 mm) 이상 거리에서 맞는다. 가까우면 오차가 커진다.
- MLP 실측 학습에는 참값 위치가 필요하다(템플릿 따라 그리기 등). 어떻게 얻을지 먼저 정한다.

### 6.2 서명 버퍼·전처리

- 프레임 `(t, x, y, z, θ, φ, pen)`, 50 Hz, 최대 6 s(300프레임). `pen`은 z 문턱 + 히스테리시스.
- 시작: 펜이 처음 내려간 순간. 끝: 펜 올림 1.0 s 지속 또는 KEY1. 펜 내림 구간 0.5 s 미만이거나 추적 끊김 프레임 20% 초과면 "다시 서명" 후 폐기.
- 정규화: 펜 내림 점의 무게중심을 원점으로, 가로 폭을 1로. z는 판 기준 높이 그대로.
- 리샘플: 시간축 128점 선형 보간(총 소요 시간은 별도 숫자). 입력 채널 8개 `x, y, z, vx, vy, θ, φ, pen`, 채널별 스케일로 int8.

### 6.3 임베딩 CNN (Tier 2, 초안)

```
입력 128×8
Conv1D  8→16, k=5, ReLU, MaxPool2   → 64×16   (~82k MAC)
Conv1D 16→32, k=5, ReLU, MaxPool2   → 32×32   (~164k MAC)
Conv1D 32→32, k=3, ReLU, MaxPool2   → 16×32   (~98k MAC)
Global Average Pool                  → 32
Dense 32→32 → L2 정규화              → 32차원 임베딩
```

총 약 34.5만 MAC, 가중치 약 7.3k개(int8 약 7 KB). triplet 또는 prototypical 손실. 등록은 서명 5개의 임베딩 평균을 기준 벡터로 저장. Nios II/e는 곱셈기가 없어 추정 약 0.7 s 이상이고, 코어 선택에 따라 크게 달라진다(실측 필요).

### 6.4 판정 규칙

```
d_k = 1 − cos(e, ref_k)          # 등록자 k와의 거리 (DTW만 쓰면 d_k = 정규화 DTW 거리)
k1, k2 = 거리가 가장 작은 두 등록자
등록자 k1 판정 ⇔ d_k1 < τ_k1  and  (d_k2 − d_k1) ≥ m  and (선택) DTW 동의
τ_k = μ_k + a·σ_k   # 등록 시 본인 서명 5개끼리의 거리 평균·표준편차
```

a, m, τ_dtw는 검증 데이터로 정하고, 미등록을 등록자로 잘못 받는 오류를 줄이는 방향으로 잡는다. DTW는 Sakoe–Chiba 대역 16, 템플릿당 약 4k 셀.

## 7. DE2 / Quartus 사양

- **Qsys:** Nios II(코어 미결), SDRAM, Character LCD IP(University Program), VGA Pixel Buffer(320×240, 백 버퍼), PIO, JTAG UART, 타이머, DTW 가속기(Avalon 사용자 정의 컴포넌트).
- **메모리 예산표를 만든다(아직 없음).** EP2C35 온칩 RAM 약 59 KB(483,840 bit). 항목: Nios II 코드·데이터, 서명 버퍼, 템플릿(1 KB × 등록자·횟수), CNN 가중치(약 7 KB)·활성값, VGA 버퍼(320×240×16비트 ≈ 150 KB는 SRAM/SDRAM). SDRAM 대역폭 공유 병목도 확인한다.
- **핀(GPIO_0, 3.3 V):** 헤더 29/30 = VCC33/GND, 1/3 = `GPIO_0[0]`/`[2]` = 버스 A SDA/SCL, 12 = GND. 확장 시 5/7(`[4]`/`[6]`), 13/15(`[10]`/`[12]`)는 예시. **핀 번호는 DE2 User Manual 확장 헤더 그림으로 반드시 재확인.** 헤더가 수 핀이라는 가정도 보드에서 확인.
- **센서 연결:** 4209 케이블(수 핀 끝) → 암-암 점퍼선 → DE2 헤더. 모듈 풀업이 병렬이 되므로 SDA/SCL 파형을 SignalTap·오실로스코프로 확인.
- **UI:** `SW[1:0]` 00 식별 / 01 등록(`SW[4:2]` 슬롯 0~7, 서명 5회) / 10 데이터 수집(JTAG UART) · `SW[5]` 추론 SW/HW · `SW[6]` 3D 자동 회전 · `KEY0` 기준 재측정 · `KEY1` 서명 끝 · `KEY2` 마지막 서명 취소. LEDG 전체 = 등록자, LEDR 3회 깜빡임 = 미등록. 7세그 = 지연(µs).
- **LCD는 16열×2행, 영문만.** 모든 문자열 길이를 코드에서 검사한다. (기획서 v2 6장 예시 `MATCH  d=0.18  OK`는 17자라 그대로 쓰면 넘친다.) 한글 이름은 PC에서 16×16 비트맵으로 만들어 온칩 ROM에.
- 미사용 핀: Unused Pins → As input tri-stated.
- Nios II/f는 무료판에서 JTAG 연결이 필요하다는 포럼 보고가 있다(확인 필요). 안 되면 PC를 연결한 채 시연한다.

## 8. DTW 가속기 요약 (상세: `docs/DTW-accelerator-design.md`)

- 입력 서명 2개(128 × 8채널 int8). 국소 거리는 채널별 절대차 합(L1, 최대 2040 → 11비트), 곱셈기 0개. `D[i][j] = d(i,j) + min(D[i-1][j], D[i][j-1], D[i-1][j-1])`, 대역 `|i−j| ≤ 16`, 대역 밖은 24비트 포화값.
- 기준 모델 `hw/dtw_ref.py`: 행 순서 DP와 안티대각선 DP가 30/30 일치. 대역 내 셀 3,952, 안티대각선 255, 한 대각선 최대 17셀. **PE 17개(또는 33개 공유), 템플릿당 약 275클럭**(추정; 이전 대화의 "PE 33개·약 200클럭"은 틀림).
- 구조: 오프셋 `d = i − j`에 대응하는 선형 시스톨릭 배열, 이웃 PE와만 통신. 자원 추정 33개 약 1만~1.3만 LE, 17개 공유 약 5천~8천 LE(합성 후 확정).
- 레지스터(Avalon-MM): CTRL 0x00, STATUS 0x04, N_TEMPL 0x08, QUERY_ADDR 0x0C, TEMPL_ADDR 0x10, CYCLES 0x14, RESULT[k] 0x40+.
- 검증: 테스트 벡터 100개(무작위 70, 동일 10, 최대 차이 10, 대역 가장자리 10) → ModelSim에서 HW = Python 100/100, Nios II SW도 일치, 보드에서 SW/HW 판정 동일.
- 측정표: 템플릿 25개 지연(SW /e 또는 /f vs HW), 합성 리포트(LE, RAM, 곱셈기, Fmax), 일치율, (선택) 템플릿 25/100/1000개 확장성.
- 정직한 한계: DTW 50회는 노트북에서도 1 ms 안에 끝난다. 이 가속기는 "DE2 없이는 불가능"이 아니라 **HW/SW 분할을 설계하고 지연·자원을 정량 비교**하는 것이 목적이다. 보고서에 이렇게 쓴다.
- 전제: DTW가 실제로 EER을 개선하는지 11/14 데이터로 확인한다. 안 되면 CNN MAC 가속으로 복귀.

## 9. 시뮬레이션 코드와 결과 (`sim/`)

| 파일 | 내용 |
|---|---|
| `sim_sensors.py` | 쌍극자 모델, 센서 배치별(4/9/16개) 위치 오차 몬테카를로, LM 다중 시작 |
| `sim_interference.py` | 외란(균일·기울기) 영향, 외란 미지수를 피팅에 넣는 경우 |
| `sim_layout_opt.py` | CRLB 기반 차분 진화 배치 최적화 + LM 몬테카를로 |
| `sim_sig_tracking.py` | 서명형 궤적(50 Hz, 3 s) 추적, 위치·기울기·속도 오차 |
| `sim_scenarios.py` | 확정 구조(모서리 ±7 cm, 자석 높이 약 10 mm, M0=0.9) 재시뮬레이션 |

**결과(전부 시뮬레이션):**

- 확정 구조(4개 모서리): xy 1.9 mm, 기울기 1.2°, 최대 0.7 mT. 참고로 판 위 30 mm 띄운 구조는 2.2 mm·4.3°, 허공 8 cm는 3.0~3.6 mm, 12 cm는 8.5 mm.
- 초기 배치 비교(z=4.5 cm, M0=0.55): 위치 xy RMS 4개 ±3 cm 1.6 mm / 9개 1.1 / 16개 0.7, 교정 오차(센서 위치 1 mm, 이득 2%) 포함 시 2.8 / 2.3 / 2.2. 기울기를 무시하면 4.9 / 4.5 / 4.4.
- 센서 배치 최적화는 이득이 없었다(음의 결과). 서명형 궤적(교정 오차 포함, 4개 ±3 cm): xy 1.72 mm, z 0.78 mm, 기울기 3.6°, 속도 오차 4.1%.
- 4개는 외란 기울기를 피팅할 수 없다(미지수 13 > 측정 12). 균일 외란은 가능.

**한계(중요):**
- 참값 생성과 추정이 같은 쌍극자 모델이다(inverse crime). 자석 비이상성·주변 철 구조물·간섭은 미반영.
- 이상적인 노이즈 3 µT, 궤적 수가 적다 → 실측은 몇 배 클 수 있다(문헌: 센서 16개 실측 약 4 mm).
- 손·소지품·스마트워치의 영향은 시뮬레이션하지 않았다. 센서 도착 후 자석 없이 손만 움직여 확인한다.
- 속도 오차는 평활 필터를 거친 참값과의 비교라 평활 손실을 포함하지 않는다.

## 10. 할 일 (우선순위 순)

**P0 — 먼저 (3장 표를 채운 뒤)**
1. MLX90393 I²C 통신 사양 정리와 Verilog I²C 마스터(주소 파라미터, 단일 측정 모드, 4개 순차 읽기, 목표 50 Hz). ModelSim 테스트벤치로 검증 후 실기.
2. 센서 읽기 → UART 로그 → PC에서 LM 기준선 위치 복원 확인(4개 모서리 판). **서명 영역(약 8×8 cm 종이) 안에서 오차를 잰다.**
3. 센서 게인·포화 범위(±50 mT 상한)와 쌍극자 근사 오차 확인.

**P1 — 데이터 수집 전**
4. **데이터 수집 모드는 위치 복원 결과뿐 아니라 센서 12채널 원시값도 함께 저장한다.** 나중에 추적기를 바꿔도 서명을 다시 계산할 수 있어야 한다. 세션 메타데이터(참가자 번호, 날짜, 역할) 포함. 수집(11/13)이 게이트 2(11/15)보다 앞서므로 필수다.
5. 평가 하네스(Python): DTW 기준선, FAR/FRR/EER, 사람별 혼동행렬, 신뢰구간.
   - **데이터 분리:** 학습·검증·테스트는 날짜로 나누고, 미등록 역할은 **문턱 결정용과 시험용 사람을 분리**한다. 인원이 적으면 leave-one-person-out.
   - 입력 채널 ablation: (x,y,pen) / +속도 / +z·θ·φ.

**P2 — 모델·하드웨어**
6. DTW HW(8장): PE 모듈 → 3 PE → 전체 배열 순으로 ModelSim, Avalon 래퍼, Qsys 통합, 자원·지연 측정. Nios II C의 SW DTW와 비트 일치.
7. Nios II C: 서명 버퍼, 전처리, 판정, LCD·LED·7세그. 메모리 예산표(7장).
8. (선택) 임베딩 CNN 학습 → int8 양자화 → Python / Nios II SW에서 비트 일치, `.hex` 출력. 공개 온라인 서명 데이터셋은 x, y, 시간(필압) 정도만 있어 z·θ·φ는 사전학습되지 않는다(해당 채널 마스킹 등으로 별도 설계, 라이선스·수업 사용 가능 여부 먼저 확인).
9. (선택) VGA 3D 표시(고정소수점 sin/cos 표, Bresenham, 백 버퍼, 한글 비트맵).

## 11. 평가 프로토콜과 미확정 사항

- **내부 목표(잠정, 방향 설정용):** 등록자 식별 정확도 ≥90%, FAR ≤10%, FRR ≤15%, 판정 시간 ≤1 s(타임아웃 1 s 제외). 못 미쳐도 실측을 그대로 보고.
- 위협 모델 3종(랜덤, 정지 이미지 보고 따라 쓰기, 서명 영상 보고 따라 쓰기)을 따로 보고. 형식: "위조 N회 중 M회 통과, 95% 신뢰구간 …". "FAR 0%"라고 쓰지 않는다. 같은 위조자가 같은 대상을 여러 번 쓴 시도는 독립이 아니다.
- **표본 크기 주의:** 미등록자 5~10명 × 10회에서 FAR 10%의 95% 신뢰구간은 대략 4~21%로 넓다. n을 명시한다.
- 비교 항목: DTW 단독 / CNN 단독 / 결합, 입력 채널별, SW 대 HW(지연·LE·곱셈기·온칩 메모리), 비트 일치.
- 참고 기준선(조건이 달라 직접 비교하지 않음): AirSignatureDB 숙련 위조 EER 2.3%(기준 서명 4개)~8.9%(1개), SVC-onGoing 최고 3.3~7.4%. 사용자가 수십~100명 이상이다.
- **교수님께 확인:** 제출 기한·발표 여부, Prompt 제출 형식(전체 로그/발췌), 외부 부품, Nios II, 서명 데이터 수집(개인정보).

## 13. 위험과 미확인 사항

- 실측 위치 오차는 시뮬레이션보다 몇 배 클 수 있다. 4개는 간섭 보정 여지가 9개보다 적다.
- 펜 올림/내림 오판(서명은 펜을 짧게 자주 든다). z 히스테리시스 조정, `pen` 대신 z를 직접 입력하는 방안 비교.
- 사람 수가 적으면 임베딩이 처음 보는 사람에게 일반화되지 않는다. 대안 순서: ① 등록자 고정 분류기 ② DTW 단독 ③ 숫자 인식 ④ 제스처 분류. 소규모 데이터에서는 DTW가 CNN보다 나을 수 있다.
- 센서 1개라도 고장나면 재주문 3~4일(예비 없음). 수령 즉시 통신·주소 확인, ESD 주의.
- 센서 주소는 A0/A1 핀 결선(납땜 필요 가능). 수령 후 실제 기본 주소 확인, 게인·포화는 실측.
- DTW 시스톨릭 타이밍(지연 정렬) 버그 → 단일 PE → 3 PE → 전체 순으로 점진 검증, 기준 모델과 클럭 단위 비교. 합성 자원 초과 시 PE 33개 → 17개 공유.
- 큰 갤러리에서는 계산이 아니라 SDRAM 대역폭이 병목(템플릿당 약 12 µs, 추정). 기본은 온칩 RAM(≤25 템플릿).
- 가격 일부는 추정. 결제 전 DigiKey KR 화면에서 가격·재고·관부가세·도착일 확인.

## 15. 제출물 운영 (Journaling · Prompt · MD)

- **Journaling:** 세션을 마칠 때 `journal/YYYY-MM-DD.md`에 초안을 남긴다. 항목: 한 일, 왜 그렇게 했는지, **실패와 원인**, 아직 모르는 것, 다음 할 일. 사용자가 읽고 고친다. 실패 기록은 이해도를 보여주는 좋은 자료다. 몰아서 쓰지 않는다.
- **Prompt:** 핵심 프롬프트와 결과(받아들인 것, 고친 것, AI가 틀렸던 사례)를 `prompts/`에 모은다. 형식은 교수님 확인 후 맞춘다.
- **MD 파일:** 최종 보고서는 MD다. 권장 구성: 주제와 창의성 포인트 → 원리(쌍극자 모델, DTW, 시스톨릭 구조) → 구현(HW/SW 분담) → 측정 결과(실측과 시뮬레이션 구분) → 한계 → AI 활용 기록(검증 방법, 틀린 사례). 11/20 리허설 이후 정리할 시간을 확보한다.
